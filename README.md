# School LMS — Интерактивная Образовательная Платформа

Интерактивная EdTech-платформа нового поколения для изучения школьного курса информатики (7–11 классы) на основе учебников К.Ю. Полякова:
* **7–9 классы** (`7-класс`, `8-класс`, `9-класс`) — обучение по **базовой программе**;
* **10–11 классы (гуманитарный профиль)** (`10-класс_базовый`, `11-класс_базовый`) — обучение по **базовой программе**;
* **10–11 классы (технологический профиль)** (`10-класс_углубленный`, `11-класс_углубленный`) — обучение по **углубленной программе**.

---

## ⚡ Ключевые Особенности и Архитектура

1. **Zero Multiple Choice Policy (Анти-угадывание):**
   * Полный запрет на тесты с выбором вариантов (радиокнопки, дропдауны с ответами).
   * **Уровень 1 (Манипуляции):** Drag-and-Drop, коммутация цепей, прямое редактирование лент/сеток, сортировка.
   * **Уровень 2 (Аналитика):** Ручной ввод вычисленных значений, трассировка алгоритмов, консольные команды.
   * **Уровень 3 (Аркада):** Аркадные механики с таймерами, банк уникальных архетипов, мгновенная реакция.
2. **Глобальный Режим Хардкора:**
   * Прохождение всех трёх уровней без единой ошибки на одном дыхании. Любая ошибка вызывает полный сброс на шаг 1 и процедурную перегенерацию данных.
3. **Нормализованная Телеметрия (Стандарты xAPI / IMS Caliper Analytics):**
   * Чёткое разделение сущностей: постоянный класс ученика (`student_class`), программа курса (`course_slug`), номер урока (`lesson_id`) и уровень (`level_number`).
   * Поддержка межкурсовых соревнований (например, срез 10-го класса на уроках 8-го класса без сброса профиля).
   * Композитные индексы SQLite (`idx_telemetry_student_cohort`, `idx_telemetry_course_lesson`) для мгновенной выборки без эвристик.
4. **Дашборд Учителя Реального Времени (`/teacher`):**
   * Мультивыбор классов через чекбоксы для соревновательных срезов между параллелями.
   * Фильтр по программам заданий («Курс задания») и динамический список тем.
   * Мульти-сортировка колонок таблицы с удержанием `Ctrl` / `Shift`.
   * Live Polling каждые 5 секунд с индикацией сетевой активности и экспорт в CSV.
5. **Ретро-награды за режим «Хардкор» (Prince of Persia 1989):**
   * Для отличившихся учащихся, прошедших все 3 уровня без единой ошибки, на этапе проектирования урока может быть настроен секретный ретро-уровень (`princeBonusLevel: N`).
   * Игра работает полностью автономно (Zero-Dependency) на базе встроенного порта PrinceJS (Phaser CE).

## 🛠 Стек Технологий

* **Фреймворк:** [Astro 5](https://astro.build/) (режим SSR, `@astrojs/node` адаптер).
* **База данных:** SQLite via `better-sqlite3`.
* **Стилизация:** Tailwind CSS v4, киберпанк / терминальный UI.
* **Песочницы:** Pyodide (Python в браузере), Web Workers, изолированные `<iframe>`.
* **Тестирование:** Playwright (трехуровневая пирамида тестов: линтинг теории, контракты телеметрии, сквозные E2E).

## 🚀 Команды Разработки

```bash
# Установка зависимостей
npm install

# Запуск локального сервера разработки
npm run dev

# Сборка продакшн-сервера
npm run build

# Быстрые тесты контрактов (линтинг теории + схема БД + аналитика учителя)
npm run test:contracts

# Запуск полного набора автотестов Playwright
npm test

# Запуск тестов в интерактивном GUI Playwright
npx playwright test --ui

# Запуск миграции базы данных телеметрии
node scripts/migrate_telemetry.js
```

## 🛡️ Изоляция Продакшна и Разработка через Git Worktree

Боевой сервер запущен на ALT Linux как `systemd`-сервис `school-lms.service` из директории `~/Projects/school-lms` (порт `3000`, `http://192.168.100.135:3000`; порт `8080` в системе занят службой `ahttpd`) и обслуживает учащихся. Во избежание сбоев сервиса и загрязнения боевой базы `telemetry.db`, **любая разработка и тестирование ведутся в изолированном дереве `git worktree` на локальном диске `ext4`**:

### 1. Создание изолированного рабочего места:
```bash
# Из основной директории ~/Projects/school-lms:
git worktree add -b type/feature-name ../school-lms-dev
ln -s "$PWD/node_modules" ../school-lms-dev/node_modules
```
*(Если ветка в `school-lms-dev` ещё в работе и не очищена, создаётся `../school-lms-dev-2`, `-3` и т.д. — удобно автоматизировать через MCP `manage_worktree`.)*

### 2. Разработка и тестирование:
Внутри каталога `~/Projects/school-lms-dev`:
* Запуск сервера разработки: `npm run dev` (порт `4321`, не конфликтует с продакшном на `3000`).
* База данных изолирована (`~/Projects/school-lms-dev/telemetry.db`).
* Прогон тестов: `npm run test:contracts` и `npm test` (при запуске из портативного `agy` с флешки: `PLAYWRIGHT_BROWSERS_PATH="$REAL_HOME/.cache/ms-playwright"`).

### 3. Очистка после сдачи задачи (PR / слияние):
```bash
# Из основной директории ~/Projects/school-lms:
rm -f ../school-lms-dev/node_modules
git worktree remove ../school-lms-dev --force
```

### 4. Регламент обновления боевого сервера после слияния в `main`:
```bash
# В основной директории ~/Projects/school-lms:
git checkout main
git pull origin main
npm install                        # При изменении package.json (в agy-portable с HOME="$REAL_HOME")
node scripts/migrate_telemetry.js  # При миграциях схемы БД
npm run build                      # Компиляция новой сборки
run-as-root "systemctl restart school-lms.service" "<пароль_root>"
```

### 5. Параллельная работа нескольких ИИ-агентов:
При одновременной работе нескольких агентов (или незавершённой ветке в первом worktree) каждому выделяется собственное изолированное дерево (`~/Projects/school-lms-dev`, `~/Projects/school-lms-dev-2`, `~/Projects/school-lms-dev-3`) с выделенными портами (`4321`, `4322`, `4323`). Подробно: [docs/ai-workflow.md](docs/ai-workflow.md).
