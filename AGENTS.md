# ИНСТРУКЦИИ ДЛЯ ИИ (DISPATCHER)

Вы работаете над образовательной платформой School LMS (на базе Astro).
**В целях экономии контекста базовая документация разделена на модули.**

> ⚠️ **КРИТИЧЕСКОЕ ПРАВИЛО: ИЗОЛЯЦИЯ ПРОДАКШНА И РАБОТА ЧЕРЕЗ GIT WORKTREE**
> Боевой сервер запущен и непрерывно обслуживает учащихся из корневой директории `D:\school-lms` (порт 8080).
> **КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТСЯ** в каталоге `D:\school-lms`:
> 1. Переключать ветки Git (`git checkout`);
> 2. Запускать сборку (`npm run build`);
> 3. Запускать dev-сервер (`npm run dev`) или автотесты (`npm test`, Playwright).
> Любое из этих действий приведет к повреждению сборки `dist/`, падению боевого сервера или загрязнению боевой базы `telemetry.db`!
>
> **ПРАВИЛО РАЗРАБОТКИ:** Вся работа ИИ-агентов ведется **ИСКЛЮЧИТЕЛЬНО** в изолированном дереве `git worktree` (по умолчанию `D:\school-lms-dev`, а при параллельной работе нескольких агентов — в выделенных `D:\school-lms-dev-2`, `D:\school-lms-dev-3`).
> По завершении задачи и создании PR агент **ОБЯЗАН** удалить свой временный worktree (`git worktree remove D:\school-lms-dev-X --force`).
> Подробный регламент: см. `docs/ai-workflow.md`.

КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТСЯ писать код по памяти или гадать. Перед выполнением любой задачи вы ОБЯЗАНЫ использовать инструмент чтения файлов, чтобы загрузить в контекст только нужную инструкцию из списка ниже:

1. **Геймдизайн (Уровни 1 и 2)** -> Читать `docs/design-levels-1-2.md`
   *(Zero Multiple Choice, Ур.1: манипуляции мышью, Ур.2: ручной ввод в поле, 3 и 5 фаз, генерация при ошибке)*
2. **Геймдизайн (Уровень 3 / Аркада)** -> Читать `docs/design-level-3.md`
   *(React/Vue, семантический визуал, прямое манипулирование (Direct Manipulation), банк уникальных аркадных архетипов, таймеры, 8-12 фаз, полный сброс при ошибке)*
3. **Калибровка сложности и кривая обучения (Difficulty Curve)** -> Читать `docs/difficulty-curve.md`
   *(Формула CCS (ИКС 1–10), возрастные коридоры 7–11 классов, пилообразная кривая Sawtooth 2-1-2 на Уровне 2, фазовые профили, плотность дистракторов, запрет Fake Difficulty)*
4. **Дизайн и верстка (UI)** -> Читать `docs/ui-styling.md`
   *(Кибер-стиль, локальный Bootstrap/Tailwind, запрет на `<style>` и CDN, эргономика органов прямого управления и регламент анимаций)*
5. **API Телеметрии, Модель Данных и Аналитика** -> Читать `docs/telemetry-api.md`
   *(Нормализованная схема SQLite: student_class, course_slug, lesson_id, level_number; формат postMessage, индексы, миграция, фильтрация учителя)*
6. **Учебный план и структура файлов** -> Читать `docs/curriculum.md`
   *(Связь с учебником Полякова: 7–9 классы — базовая программа, 10–11 гуманитарный — базовая, 10–11 технологический — углубленная; папка `wp/`, структура `src/`, запрет LaTeX и правила оформления формул в учебном виде)*
7. **Готовые компоненты (Терминал, Python IDE, Prince of Persia)** -> Читать `docs/components.md`
   *(Описание пропсов и использования `Terminal.astro`, `PythonIDE.astro`, `PrinceEmulator.astro` и настройка бонуса `princeBonusLevel`)*
8. **Рабочий процесс ИИ (AI Workflow, Worktree, Параллельная работа агентов и Оформление багов)** -> Читать `docs/ai-workflow.md`
   *(Изоляция боевого сервера, параллельные worktree D:\school-lms-dev-X, гигиена веток, оформление багов через GitHub Issues/CLI, регламент обновления продакшна и чек-лист качества)*
9. **Обязательное тестирование уроков** -> Читать `docs/testing.md`
   *(Требования к e2e тестам на Playwright, проверка телеметрии и хардкор-режима)*
