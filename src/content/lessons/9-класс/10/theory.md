## 1. Граф и его основные элементы

При моделировании дорожных сетей, электрических схем, компьютерных сетей и родословных деревьев часто важно показать не свойства отдельных объектов, а **связи** между ними. Для наглядного описания систем таких связей в информатике и математике используют **<span data-term="граф" data-definition="математическая модель, состоящая из множества вершин и соединяющих их связей">граф</span>**.

Граф задаётся двумя множествами: множеством точек (объектов) и множеством линий (связей между ними).

* **<span data-term="вершина графа" data-definition="элемент графа, изображаемый точкой или кругом и обозначающий отдельный объект">Вершина графа</span>** (узел) — отдельный объект моделируемой системы (город, перекрёсток, сервер, этап работы). На рисунке обозначается точкой или кружком с буквой или цифрой.
* **<span data-term="ребро графа" data-definition="линия без направления, соединяющая две вершины неориентированного графа">Ребро графа</span>** — неопределённая по направлению линия, соединяющая две вершины. По ребру можно двигаться в обе стороны (как по двусторонней дороге).
* **<span data-term="дуга графа" data-definition="направленная линия со стрелкой, соединяющая вершины ориентированного графа">Дуга графа</span>** — направленная связь со стрелкой, указывающей допустимое направление перехода от одной вершины к другой (как улица с односторонним движением).
* **Степень вершины** — количество рёбер, выходящих из данной вершины. В любом графе сумма степеней всех вершин в два раза больше количества рёбер, так как каждое ребро имеет два конца.
* **Петля** — ребро или дуга, выходящие из вершины и входящие в неё же саму.
* **Цикл** — замкнутый маршрут по рёбрам или дугам графа, который начинается и заканчивается в одной и той же вершине.

### Основные разновидности графов

1. **Неориентированный граф** — все связи равноправны и двусторонни (рёбра без стрелок).
2. **<span data-term="ориентированный граф" data-definition="граф, связи в котором имеют строго заданное направление от одной вершины к другой">Ориентированный граф</span> (орграф)** — связи задаются дугами со стрелками; существование пути из `A` в `B` не гарантирует возможности вернуться напрямую из `B` в `A`.
3. **<span data-term="взвешенный граф" data-definition="граф, каждому ребру или дуге которого сопоставлено числовое значение веса">Взвешенный граф</span>** — граф, у каждого ребра или дуги которого указано число — **вес**. Весом могут выступать расстояние в километрах, время поездки, стоимость перелёта или пропускная способность канала связи.

```
   НЕОРИЕНТИРОВАННЫЙ             ОРИЕНТИРОВАННЫЙ               ВЗВЕШЕННЫЙ
       (без весов)                   (орграф)                 (с длинами дорог)

       (A)─────(B)                  (A)────►(B)                 (A)───4───(B)
        │       │                    │       ▲                   │         │
        │       │                    ▼       │                   7         2
        │       │                    │       │                   │         │
       (C)─────(D)                  (C)────►(D)                 (C)───5───(D)
```

## 2. Табличное представление графа: весовая матрица

Рисунок графа удобен для зрительного восприятия человеком, но компьютер не «видит» картинку — ему необходима строгая числовая структура данных. Такую структуру мы уже рассматривали в теме табличных моделей: для представления связей применяют квадратные таблицы «Объект — Объект».

Если в таблице отмечают только сам факт наличия связи (`1` — ребро есть, `0` — ребра нет), её называют **матрицей смежности**. Если же в ячейки записывают числовые характеристики рёбер (расстояния, затраты времени, стоимости), таблицу называют **<span data-term="весовая матрица" data-definition="квадратная таблица, содержащая числовые веса ребер между парами вершин графа">весовой матрицей</span>** (или матрицей расстояний / стоимостей).

### Пример: взвешенный граф дорог и его весовая матрица

Пусть между пятью посёлками `A`, `B`, `C`, `D`, `E` проложены двусторонние дороги известной длины (в километрах):

| Пункт | A | B | C | D | E |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **A** | | 4 | 9 | | |
| **B** | 4 | | 2 | 7 | |
| **C** | 9 | 2 | | 3 | 8 |
| **D** | | 7 | 3 | | 2 |
| **E** | | | 8 | 2 | |

```
                  4
           (A)─────────(B)
             \         / \
              \       2   7
               9     /     \
                \   /   3   \
                 (C)─────────(D)
                   \         /
                    8       2
                     \     /
                      \   /
                       (E)
```

### Ключевые свойства весовой матрицы:

1. **Размерность `N × N`:** Число строк и число столбцов совпадает и равно количеству вершин графа `N`.
2. **Главная диагональ:** Ячейки на пересечении одинаковых вершин (`A–A`, `B–B`, `C–C`, `D–D`, `E–E`) обычно оставляют пустыми или ставят `0` (если в графе нет петель).
3. **Пустые ячейки (или прочерки):** Означают отсутствие прямой дороги между парой вершин. В компьютерных алгоритмах вместо пустоты часто используют символ бесконечности `∞`.
4. **Симметричность для неориентированного графа:** Так как дороги двусторонние, длина пути из `B` в `C` равна длине пути из `C` в `B`: `w<sub>BC</sub> = w<sub>CB</sub> = 2`. Поэтому достаточно просмотреть только часть таблицы выше (или ниже) главной диагонали, чтобы восстановить все рёбра.
5. **Несимметричность для орграфа:** Если граф ориентированный, ячейка на пересечении строки `i` и столбца `j` хранит вес дуги именно **от `i` к `j`** (`i → j`). При этом `w<sub>ij</sub>` может отличаться от `w<sub>ji</sub>`, а обратная дуга может вообще отсутствовать.

### Как восстановить граф по весовой матрице (алгоритм для ОГЭ)

1. Выпишите на черновик все вершины графа по кругу (чтобы линии меньше пересекались).
2. Просмотрите таблицу построчно **выше главной диагонали** (для неориентированного графа).
3. Для каждого непустого числа на пересечении строки `X` и столбца `Y` проведите ребро `X—Y` и подпишите рядом его вес.
4. **Проверка:** посчитайте количество чисел в каждой строке таблицы — оно должно точно совпадать со степенью соответствующей вершины на вашем рисунке.

## 3. Путь в графе и длина пути. Поиск кратчайшего маршрута

Двигаясь от вершины к вершине по соединяющим их рёбрам (или по направлению стрелок-дуг), мы совершаем маршрут.

> [!NOTE]
> **Определение:**  
> **<span data-term="путь в графе" data-definition="последовательность вершин, в которой каждая следующая связана с предыдущей ребром или дугой">Путь в графе</span>** — это конечная последовательность вершин `v<sub>0</sub>, v<sub>1</sub>, v<sub>2</sub>, ..., v<sub>k</sub>`, в которой каждая пара соседних вершин соединена ребром (или дугой в нужном направлении).  
> **<span data-term="длина пути" data-definition="сумма весов всех ребер или количество переходов на маршруте между двумя вершинами">Длина пути</span>** во взвешенном графе равна сумме весов всех рёбер, входящих в этот путь (в невзвешенном графе длиной пути считают количество пройденных рёбер).

Путь называют **простым**, если в нём ни одна вершина не встречается дважды. При поиске кратчайшего маршрута с положительными весами заходить в одну и ту же вершину повторно бессмысленно — это лишь увеличит итоговую длину.

### Практический разбор: поиск кратчайшего пути (Задание 4 ОГЭ)

Используем приведённую выше весовую матрицу для пунктов `A, B, C, D, E`. Найдём **длину кратчайшего пути между `A` и `E`** (передвигаться можно только по дорогам, указанным в таблице).

Обратите внимание на важную ловушку: прямой дороги `A—E` нет, а очевидный короткий шаг `A → C → E` даёт сумму `9 + 8 = 17` км. Проверим все простые пути от `A` к `E`, построив дерево возможных продолжений (перебор с отсечением повторных вершин):

```
                           (A)
                         /     \
                       4/       \9
                       ▼         ▼
                     (B)         (C)
                    /   \        / | \
                  2/    7\     2/ 3|  \8
                  ▼       ▼    ▼   ▼   ▼
                (C)      (D) (B)  (D)  (E) [17]
               /   \      |   |   / \
             3/    8\    2|  7| 7/   \2
             ▼       ▼    ▼   ▼ ▼     ▼
            (D)     (E)  (E) (D)...  (E) [14]
             |      [14] [13] |
            2|               2|
             ▼                ▼
            (E) [11]         (E) [20]
```

Выпишем основные маршруты и их длины:
* `A → C → E` = `9 + 8 = 17` км;
* `A → C → D → E` = `9 + 3 + 2 = 14` км;
* `A → B → C → E` = `4 + 2 + 8 = 14` км;
* `A → B → D → E` = `4 + 7 + 2 = 13` км;
* `A → B → C → D → E` = `4 + 2 + 3 + 2 = 11` км.

**Ответ:** длина кратчайшего пути равна **11 км** (маршрут `A → B → C → D → E`).

> [!TIP]
> **Вывод для экзамена:** Кратчайшим часто оказывается составной маршрут с большим числом пересадок, но с маленькими весами отдельных участков. Не ограничивайтесь путями из 2–3 звеньев — проверяйте обходные ветки через соседние узлы.

### Вариант с обязательным или запрещённым пунктом

В задачах повышенного внимания (в том числе в ОГЭ) часто ставят дополнительное условие:
1. **«Путь должен проходить через пункт `C`»:** сначала находим кратчайший путь от старта до `C`, затем отдельно кратчайший путь от `C` до финиша (без повторного посещения уже пройденных вершин) и складываем длины.
2. **«Путь НЕ должен проходить через пункт `D`»:** мысленно вычёркиваем вершину `D` и все инцидентные ей рёбра (соответствующие строку и столбец матрицы), после чего ищем минимум на оставшемся графе.

## 4. Вычисление количества путей в направленном ациклическом графе (Задание 9 ОГЭ)

Если на схеме дорог все связи односторонние и организованы так, что, выехав из города, нельзя вернуться в него снова ни по какому маршруту, перед нами **<span data-term="направленный ациклический граф" data-definition="ориентированный граф, в котором отсутствуют замкнутые маршруты и циклы">направленный ациклический граф</span>** (в программировании его часто обозначают аббревиатурой **DAG** — *Directed Acyclic Graph*).

В таком графе всегда можно упорядочить вершины от истока (начала) к стоку (концу) так, чтобы все стрелки вели строго вперёд. Благодаря отсутствию циклов количество различных путей между двумя вершинами всегда конечно и вычисляется точным пошаговым суммированием — без перебора всех маршрутов вручную.

### Правило суммы входящих путей (динамический подсчёт)

Пусть требуется найти количество различных путей из начальной вершины `S` в конечную вершину `T`. Обозначим через `N(X)` число различных путей, ведущих из `S` в вершину `X`.

1. **Начальное условие:** Для стартовой вершины принимаем `N(S) = 1` (в начало маршрута ведёт ровно один «пустой» путь).
2. **Рекуррентное правило:** Для любой другой вершины `V` количество путей равно сумме количеств путей во все вершины `U<sub>1</sub>, U<sub>2</sub>, ..., U<sub>k</sub>`, из которых идут прямые стрелки в `V`:
   `N(V) = N(U<sub>1</sub>) + N(U<sub>2</sub>) + ... + N(U<sub>k</sub>)`
3. **Порядок вычисления:** Значение `N(V)` можно вычислять только тогда, когда уже подсчитаны значения для **всех** вершин, из которых входят стрелки в `V`.

### Пошаговый пример вычисления количества путей

Рассмотрим схему односторонних дорог, ведущую из города `А` в город `Е`:

```
                 ┌──────►(Б)──────┐
                 │        │       │
                 │        ▼       ▼
                (А)─────►(В)─────►(Д)─────►(Е)
                 │        ▲       ▲        ▲
                 │        │       │        │
                 └──────►(Г)──────┴────────┘
```
*(Стрелки на схеме: `А → Б`, `А → В`, `А → Г`; `Б → В`, `Б → Д`; `Г → В`, `Г → Д`, `Г → Е`; `В → Д`; `Д → Е`.)*

Вычислим число путей из `А` в каждую вершину последовательно:

| Вершина | Входящие дуги (откуда можно попасть) | Формула расчёта | Количество путей `N` |
| :---: | :--- | :--- | :---: |
| **А** | Старт маршрута | Базовое значение | **1** |
| **Б** | из `А` | `N<sub>Б</sub> = N<sub>А</sub> = 1` | **1** |
| **Г** | из `А` | `N<sub>Г</sub> = N<sub>А</sub> = 1` | **1** |
| **В** | из `А`, `Б`, `Г` | `N<sub>В</sub> = N<sub>А</sub> + N<sub>Б</sub> + N<sub>Г</sub> = 1 + 1 + 1` | **3** |
| **Д** | из `Б`, `В`, `Г` | `N<sub>Д</sub> = N<sub>Б</sub> + N<sub>В</sub> + N<sub>Г</sub> = 1 + 3 + 1` | **5** |
| **Е** | из `Д`, `Г` | `N<sub>Е</sub> = N<sub>Д</sub> + N<sub>Г</sub> = 5 + 1` | **6** |

Обратите внимание: вершину `В` нельзя было считать раньше `Б` и `Г`, потому что стрелки в `В` приходят не только из `А`, но и из `Б` и `Г`. Итого из `А` в `Е` существует ровно **6** различных путей.

### Частые ограничения в задачах на подсчёт путей:

1. **Пути, НЕ проходящие через вершину `X`:**  
   Перед началом подсчёта просто вычеркните вершину `X` и все входящие/исходящие из неё стрелки (или положите `N(X) = 0`). Например, если в приведённой выше схеме запрещено заезжать в город `В`, то `N<sub>В</sub> = 0`, откуда `N<sub>Д</sub> = N<sub>Б</sub> + N<sub>Г</sub> = 1 + 1 = 2`, а `N<sub>Е</sub> = 2 + 1 = 3`.
2. **Пути, ОБЯЗАТЕЛЬНО проходящие через вершину `X`:**  
   Есть два равносильных способа:
   * *Способ вычёркивания лишних дуг:* Удалите со схемы все стрелки, которые **обходят** обязательный пункт `X` стороной (не позволяют в него попасть или ведут в обход него после развилки), а затем выполните стандартный подсчёт сумм.
   * *Способ перемножения этапов:* Посчитайте число путей из старта `S` до обязательной вершины `X` (`k<sub>1</sub>`), затем примите `N(X) = 1` и отдельно посчитайте число путей из `X` до финиша `T` (`k<sub>2</sub>`). Общее число путей равно произведению `k<sub>1</sub> × k<sub>2</sub>`.

## 5. Применение графов и DAG в реальной IT-индустрии

Теория графов — не абстрактная школьная тема, а один из главных рабочих инструментов современной разработки ПО:

* **Навигаторы и картографические сервисы:** Карты городов (Яндекс Карты, 2ГИС) хранятся в виде огромных взвешенных ориентированных графов, где перекрёстки — вершины, а участки дорог — дуги, вес которых динамически меняется в зависимости от пробок. Поиск маршрута опирается на алгоритмы поиска кратчайшего пути (Дейкстры и `A*`).
* **Маршрутизация в Интернете:** Магистральные роутеры используют протоколы состояния каналов (например, `OSPF`), строя весовую матрицу задержек между узлами сети и направляя пакеты данных по самому быстрому пути.
* **Системы контроля версий и сборки проектов:** История коммитов в **Git**, конвейеры **CI/CD** и зависимости формул в **электронных таблицах** представляют собой **направленные ациклические графы (DAG)**. Зависимости задач выполняются строго в топологическом порядке — система не запустит сборку модуля, пока не завершены все предшествующие ему узлы графа.
* **Социальные сети и антифрод:** Профили пользователей образуют гигантский граф подписок и контактов. Поиск «общих друзей», расчёт «теории шести рукопожатий» и выявление цепочек подозрительных банковских транзакций выполняются алгоритмами обхода графов.
