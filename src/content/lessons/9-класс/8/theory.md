# Теоретическая база: Табличные модели

> **Параллель и профиль:** 9 класс (базовый уровень, подготовка к ОГЭ)  
> **Учебный модуль:** Информационное моделирование  
> **Базовый источник:** УМК К.Ю. Полякова и Е.А. Еремина (Информатика 9 класс, ФГОС ООО)

## 1. Таблицы как универсальный инструмент структурирования данных

Среди всего многообразия информационных моделей **<span data-term="табличная модель" data-definition="информационная модель, данные в которой организованы в виде строк и столбцов">табличная модель</span>** является наиболее распространенной, компактной и удобной для человеческого восприятия и компьютерной обработки.

Таблица состоит из прямоугольной сетки пересекающихся строк и столбцов (колонок). На их пересечении образуются элементарные ячейки данных.

### Преимущества табличных моделей:
* **Компактность и наглядность:** Большой объем фактов и числовых измерений представляется в обозримом виде без длинных словесных описаний;
* **Легкость сопоставления:** Свойства однотипных объектов выравниваются по столбцам, что позволяет мгновенно сравнивать их между собой;
* **Алгоритмическая простота:** Таблицы являются естественной формой представления данных для реляционных баз данных, электронных таблиц и языков программирования (массивы и матрицы).

## 2. Таблицы типа «Объект — Свойство» (ОС)

В таблицах типа **<span data-term="объект-свойство" data-definition="таблица, где строки соответствуют отдельным объектам, а столбцы — их характеристикам">«Объект — Свойство»</span>** каждая строка посвящена описанию одного отдельного объекта реального мира, а столбцы фиксируют конкретные характеристики (свойства, атрибуты) этих объектов.

```
       ┌─────────────────────── СТОЛБЦЫ (Свойства) ───────────────────────┐
       ▼                                                                  ▼
┌──────────────┬──────────────────┬───────────────┬────────────────────────┐
│   Объект     │  Характеристика 1 │ Характеристика 2 │ Характеристика 3 ...   │ ◄── Шапка (Заголовок)
├──────────────┼──────────────────┼───────────────┼────────────────────────┤
│  Объект №1   │     значение     │   значение    │       значение         │ ◄── Строка (Запись)
│  Объект №2   │     значение     │   значение    │       значение         │
│  Объект №3   │     значение     │   значение    │       значение         │
└──────────────┴──────────────────┴───────────────┴────────────────────────┘
```

### Пример таблицы «Объект — Свойство» (Характеристики планет):

| Планета | Тип планеты | Экваториальный радиус (км) | Масса (в массах Земли) | Наличие колец |
| :--- | :--- | :--- | :--- | :--- |
| Меркурий | Земная группа | 2440 | 0.055 | Нет |
| Венера | Земная группа | 6052 | 0.815 | Нет |
| Земля | Земная группа | 6378 | 1.000 | Нет |
| Марс | Земная группа | 3396 | 0.107 | Нет |
| Юпитер | Газовый гигант | 71492 | 317.8 | Да |
| Сатурн | Газовый гигант | 60268 | 95.2 | Да |

В этой модели:
* Каждый отдельный объект (строка) — это конкретная планета;
* Свойства (столбцы) — это ее тип, радиус, масса и наличие кольцевой системы;
* Каждая ячейка содержит конкретное значение конкретного свойства для конкретного объекта.

В компьютерных базах данных (реляционных СУБД) строка такой таблицы называется **<span data-term="запись таблицы" data-definition="строка таблицы, содержащая совокупность всех характеристик одного объекта">записью таблицы</span>**, а столбец — **<span data-term="поле таблицы" data-definition="столбец таблицы, содержащий значения определенного свойства объектов">полем таблицы</span>**. Поле, значения которого уникальны для каждой строки (например, табельный номер, артикул, ИНН), называют **<span data-term="первичный ключ" data-definition="поле таблицы, однозначно идентифицирующее каждую ее запись">первичным ключом</span>**.

## 3. Таблицы типа «Объект — Объект» (ОО)

Таблицы типа **<span data-term="объект-объект" data-definition="таблица, отражающая взаимные отношения между парами объектов">«Объект — Объект»</span>** используются для фиксации отношений, связей и взаимодействий между парами объектов (однотипных или принадлежащих разным классам).

В таких таблицах:
* Заголовки строк содержат перечень одних объектов;
* Заголовки столбцов содержат перечень других (или тех же самых) объектов;
* В ячейках на пересечении строк и столбцов указывается характер отношения между ними (наличие связи, числовой показатель, расстояние, оценка, результат встречи).

### Пример 1: Таблица посещаемости факультативов (Разнотипные объекты «Ученик — Кружок»):

| Ученик | Робототехника | Веб-разработка | Олимпиадная математика | Шахматы |
| :--- | :---: | :---: | :---: | :---: |
| Алексеев А. | + | - | + | - |
| Борисов В. | - | + | - | + |
| Васильева Е. | + | + | + | - |
| Громов Д. | - | - | - | + |

Знак `+` фиксирует факт посещения кружка данным учеником, а знак `-` — отсутствие участия. Это пример качественного бинарного отношения.

### Пример 2: Таблица типа «Объект — Объект» для однотипных объектов (Турнирная таблица):
В турнирной таблице спортивного турнира строки и столбцы содержат имена одних и тех же участников, а ячейки показывают счет сыгранного матча.

## 4. Двоичные матрицы и графы

**<span data-term="двоичная матрица" data-definition="таблица, содержащая только нули и единицы для фиксации наличия качественных свойств">Двоичная матрица</span>** — это таблица, ячейки которой могут принимать строго два значения: `1` (свойство есть, связь существует, отношение истинно) и `0` (свойства нет, связи нет, отношение ложно).

Двоичные матрицы служат основным математическим аппаратом для представления графов на компьютере.

```
                  НЕОРИЕНТИРОВАННЫЙ ГРАФ              МАТРИЦА СМЕЖНОСТИ
                           (A)                                A  B  C  D
                          /   \                            A [0, 1, 1, 0]
                         /     \                           B [1, 0, 1, 1]
                       (B)─────(C)                         C [1, 1, 0, 1]
                         \     /                           D [0, 1, 1, 0]
                          \   /
                           (D)
```

**<span data-term="матрица смежности" data-definition="квадратная таблица, отображающая наличие и веса связей между вершинами графа">Матрица смежности</span>** графа — это квадратная таблица, размерность которой равна количеству вершин графа. На пересечении строки `i` и столбца `j` ставится `1`, если между вершинами `i` и `j` есть ребро (связь), и `0`, если ребра нет.

### Фундаментальные свойства матрицы смежности:
1. **<span data-term="главная диагональ" data-definition="диагональ квадратной матрицы от левого верхнего угла к правому нижнему">Главная диагональ</span>:** Линия ячеек, идущая от верхнего левого угла к правому нижнему (ячейки `A-A`, `B-B`, `C-C`, `D-D`). Если граф не имеет петель (ребер, соединяющих вершину саму с собой), на главной диагонали всегда стоят нули.
2. **<span data-term="симметричная матрица" data-definition="квадратная матрица, элементы которой зеркально равны относительно главной диагонали">Симметричная матрица</span>:** Если граф **неориентированный** (движение по ребрам возможно в обе стороны), матрица смежности всегда строго симметрична относительно главной диагонали: значение в ячейке `(i, j)` тождественно равно значению в ячейке `(j, i)`.
3. **Ориентированный граф (орграф):** Если ребра имеют направление (стрелки), симметрия нарушается, так как наличие ребра из `A` в `B` не означает существование обратного ребра из `B` в `A`.

## 5. Числовые весовые матрицы (Матрицы расстояний)

Если ребрам графа сопоставлены числовые величины (длина дороги в километрах, стоимость проезда в рублях, пропускная способность канала связи в Мбит/с), граф называют **взвешенным**, а таблицу — **<span data-term="весовая матрица" data-definition="квадратная числовая таблица с длинами ребер или стоимостями переходов в графе">весовой матрицей</span>** (или матрицей расстояний).

### Пример матрицы расстояний между населенными пунктами:

| Населенный пункт | A | B | C | D | E |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **A** | | 3 | 5 | | |
| **B** | 3 | | 1 | 4 | |
| **C** | 5 | 1 | | 2 | 6 |
| **D** | | 4 | 2 | | 2 |
| **E** | | | 6 | 2 | |

* **Пустые ячейки:** Означают отсутствие прямого дорожного сообщения между данными пунктами (в алгоритмических расчетах принимаются равными бесконечности `∞`).
* **Симметрия относительно диагонали:** Расстояние от `A` до `B` (3 км) в точности равно расстоянию от `B` до `A` (3 км), так как дороги двусторонние.
* **Главная диагональ пуста:** Расстояние от пункта до самого себя равно `0` и в таблице не заполняется.

## 6. Табличные модели в заданиях ОГЭ по информатике

В Основном государственном экзамене (ОГЭ) по информатике умение работать с табличными моделями проверяется в нескольких профильных задачах:

1. **Задание 4 ОГЭ (Поиск кратчайшего пути по таблице расстояний):**
   * Дана весовая матрица дорог между пунктами `A, B, C, D, E, F`.
   * Требуется найти длину кратчайшего пути между двумя заданными пунктами, проходящего через определенный промежуточный узел (или не проходящего через него).
   * **Алгоритм решения:** Табличную модель переводят в наглядную графическую модель (строят взвешенный граф на черновике), расставляют длины ребер и методом перебора ветвей дерева путей вычисляют минимальную сумму.
2. **Задание 9 ОГЭ (Подсчет количества путей в ориентированном графе):**
   * Схема дорог может быть задана списком смежности или матрицей переходов.
   * Количество путей в целевой пункт вычисляется как сумма путей во все непосредственно предшествующие ему пункты: `N<sub>E</sub> = N<sub>B</sub> + N<sub>C</sub> + N<sub>D</sub>`.
3. **Задание 3 и 8 ОГЭ (Анализ реляционных таблиц и логические условия):**
   * В реляционной таблице требуется подсчитать количество записей, удовлетворяющих сложному составному условию с операторами `И` (логическое умножение), `ИЛИ` (логическое сложение) и `НЕ` (отрицание).

## 7. Применение в реальной IT-индустрии

Табличные модели составляют фундамент современной индустрии обработки информации:
1. **Реляционные базы данных (<span data-term="реляционная таблица" data-definition="таблица базы данных, состоящая из строк-записей и столбцов-полей">реляционная таблица</span>):** СУБД (PostgreSQL, MySQL, SQLite, Oracle) хранят терабайты данных именно в виде нормализованных таблиц. Язык SQL специально спроектирован для выборки строк по условиям (`WHERE`), сортировки (`ORDER BY`) и объединения таблиц (`JOIN`).
2. **Анализ данных и Data Science:** Библиотека **Pandas** в Python использует табличные структуры `DataFrame`, позволяющие выполнять сложнейшую фильтрацию, группировку и агрегацию миллионов строк данных в памяти.
3. **Графовые движки и сетевая маршрутизация:** Сетевые коммутаторы и интернет-маршрутизаторы (таблицы маршрутизации, протоколы OSPF и BGP) используют матрицы смежности и алгоритм Дейкстры для нахождения оптимальных маршрутов передачи IP-пакетов по оптоволоконным магистралям.

## Дополнительная информация

### Для уровня 1 (Базовый)

#### 1. Четкий критерий разделения таблиц «Объект — Свойство» и «Объект — Объект»
При классификации табличных моделей в инженерной практике ключевым является анализ семантики строк и столбцов:
* **Таблицы «Объект — Свойство» (ОС):**
  * В строках перечисляются **автономные, независимые сущности** (конкретные объекты материального мира или информационной системы).
  * В столбцах указываются **характеристики, качества и атрибуты** этих сущностей (числовые параметры, строковые описания, категории).
  * Каждая ячейка описывает отдельное свойство одного конкретного объекта.
  * *Дидактический пример:* Каталог редких книг библиотеки, где в строках указаны инвентарные номера книг, а в столбцах — «Автор», «Год издания», «Язык оригинала», «Количество страниц».
* **Таблицы «Объект — Объект» (ОО):**
  * И строки, и столбцы содержат **названия взаимодействующих объектов** (одного или различных классов).
  * Ячейки на пересечении строки и столбца выражают **отношение, связь, взаимодействие, дистанцию или результат контакта** между парой объектов.
  * *Дидактический пример:* Матрица взаимного цитирования научных журналов (строки — цитирующие журналы, столбцы — цитируемые журналы, ячейки — количество ссылок); таблица времени полета между городами.

#### 2. Законы конструирования двоичной матрицы смежности графа
При представлении неориентированного графа в виде матрицы смежности действуют строгие математические инварианты:
* **Размерность матрицы:** Квадратная таблица размерностью N × N, где N — общее число вершин графа.
* **Главная диагональ:** Проходит от верхнего левого угла (1, 1) до нижнего правого (N, N). Если в графе нет петель (ребер, соединяющих вершину саму с собой), на главной диагонали **всегда стоят нули**.
* **Симметрия неориентированного ребра:** Если между вершинами U и V есть ребро, движение по нему возможно в обоих направлениях. Поэтому в матрице выставляются ровно **две единицы**: в ячейке `(U, V) = 1` и в симметричной ячейке `(V, U) = 1`.
* **Проверка корректности:** При мысленном перегибе таблицы по главной диагонали все единицы верхнего треугольника обязаны зеркально совпасть с единицами нижнего треугольника.

#### 3. Восстановление числовых весовых матриц (матриц расстояний)
Весовая матрица дорог фиксирует длины ребер взвешенного графа.
* Если связь между пунктами P и Q двусторонняя, то `w(P, Q) = w(Q, P)`.
* При восстановлении поврежденных ячеек весовой таблицы значение пустой ячейки `(P, Q)` однозначно определяется либо из схемы графа (длина ребра между P и Q), либо из парной зеркальной ячейки `(Q, P)`.

### Для уровня 2 (Продвинутый)

#### 1. Экспресс-расчет числа ребер по матрице смежности (Шаг 1)
В неориентированном графе без петель каждое ребро связывает две различные вершины и фиксируется в матрице смежности двумя единицами: одна в верхнем треугольнике таблицы, вторая — зеркально в нижнем.
* **Формула расчета общего числа ребер E:**
  `E = (Сумма всех единиц в таблице) / 2`
* **Быстрый метод подсчета:** Достаточно сосчитать единицы только строго выше (или строго ниже) главной диагонали. Полученное число и есть точное количество ребер графа.

#### 2. Дерево путей и поиск кратчайшего маршрута (Шаг 2 — ОГЭ Задание 4)
При поиске кратчайшего пути между начальным пунктом A и конечным пунктом D по таблице расстояний:
1. **Построение дерева перебора:**
   * От начального пункта A выписываются все доступные прямые дороги в соседние пункты.
   * Для каждого соседа продолжается ветвление до тех пор, пока ветвь не придет в целевой пункт D (или не зайдет в тупик).
   * Повторное посещение уже пройденных в текущей ветке пунктов запрещено (исключение циклов).
2. **Ловушка прямой дороги:**
   * Наличие прямого пути `A → D` в таблице не гарантирует его минимальность. В реальных задачах обходной путь через один или два промежуточных пункта (например, `A → B → C → D`) зачастую оказывается значительно короче прямого шоссе.
   * Всегда суммируйте длины всех альтернативных маршрутов и сравнивайте их величины.

#### 3. Реверсивный анализ и уравнение скрытого параметра X (Шаг 3 — Пик 1)
Если длина одного из участков дороги скрыта переменной `X`, а общая длина кратчайшего пути `L` задана в условии:
1. Вычислите длины всех известных альтернативных путей, не зависящих от `X`.
2. Если альтернативные маршруты длиннее заданного значения `L`, значит, кратчайшим является путь, включающий ребро `X`.
3. Составьте линейное уравнение для этого пути:
   `L = X + w(остальные звенья маршрута)`
4. Выразите искомый вес `X`:
   `X = L - w(остальные звенья маршрута)`
5. Проверьте физическую адекватность: значение `X` обязано быть положительным целым числом (`X > 0`).

#### 4. Логическая фильтрация в реляционных базах данных (Шаг 4 — Долина)
При анализе строк таблицы «Объект — Свойство» по логическому условию запроса:
* **Оператор конъюнкции (И):** Условие `(Критерий_1) И (Критерий_2)` истинно для строки тогда и только тогда, когда оба критерия выполняются одновременно.
* **Оператор инверсии (НЕ):** Конструкция `НЕ (Поле = Значение)` означает, что значение поля должно быть не равно указанному (`Поле ≠ Значение`).
* **Алгоритм проверки:** Проверяйте каждую запись таблицы последовательно. Если первое условие дает ложь, строку можно сразу отбросить (ленивая оценка конъюнкции). Подсчитайте суммарное количество строк, для которых все составляющие части сложного условия истинны.

#### 5. Декомпозиция маршрута с обязательным промежуточным пунктом (Шаг 5 — Кульминация)
Если по условию задачи требуется найти кратчайший путь из пункта A в пункт E, **обязательно проходящий через промежуточный пункт C**:
* Задача строго разделяется на две независимые последовательные подзадачи:
  1. Найти кратчайший путь из старта в обязательный пункт: `L<sub>1</sub> = Min(A → C)`.
  2. Найти кратчайший путь из обязательного пункта в финиш: `L<sub>2</sub> = Min(C → E)`.
* **Итоговая длина кратчайшего маршрута:**
  `L<sub>общ</sub> = L<sub>1</sub> + L<sub>2</sub>`
* **Категорический запрет:** Маршруты, проходящие напрямую из A в E в обход пункта C, рассматривать запрещено, даже если их длина меньше полученной суммы.

### Для уровня 3 (Аркада)

#### 1. Архитектурный протокол попеременного обхода матрицы (Cyber Matrix)
Механика взлома буфера таблицы подчиняется жесткому правилу ортогональных направляющих:
* **Старт сеанса:** Первый ход всегда осуществляется строго в **первой строке** матрицы (`Строка 1`).
* **Переключение направляющей:**
  * Выбор ячейки в активной строке на столбце C фиксирует токен ячейки в буфер памяти и активирует **столбец C**.
  * Следующий выбор ячейки в активном столбце C на строке R активирует **строку R**.
  * Траектория движения представляет собой непрерывный ортогональный зигзаг: `Строка → Столбец → Строка → Столбец`.
* Повторное использование уже выбранной ячейки матрицы запрещено.

#### 2. Стратегия сборки целевой цепочки токенов
* **Планирование на 2–3 шага вперед:** Прежде чем нажать на первый токен требуемой последовательности в первой строке, визуально убедитесь, что в столбце этого токена существует переход ко второму целевому токену.
* **Тактический маневр через буфер (буферная подушка):**
  Целевая последовательность считается собранной, если ее токены идут в буфере строго подряд. Если емкость буфера больше длины цепочки (например, буфер 5 слотов, а цепочка из 3 токенов), игрок имеет право сделать 1–2 «холостых» хода нейтральными токенами, чтобы перевести активную направляющую в нужный квадрант матрицы, после чего собрать целевую цепочку.
* **Защита от переполнения:** Заполнение всех слотов буфера памяти без собранной целевой последовательности немедленно вызывает аварийный сброс.

#### 3. Эргономика управления и временное сжатие
* Время на волну непрерывно сжимается от 14 до 7 секунд.
* Для исключения потерь времени на перемещение курсора мыши используйте **цифровые горячие клавиши** `1`..`6`. Нажатие клавиши `1` активирует первую ячейку в текущей подсвеченной направляющей, клавиша `2` — вторую и так далее.
* **Хладнокровие под таймером:** Первые 1.5–2 секунды каждой волны используйте исключительно для визуальной оценки матрицы и поиска траектории, не совершая хаотичных кликов. Нажатие ячейки вне активной направляющей блокируется системой.
