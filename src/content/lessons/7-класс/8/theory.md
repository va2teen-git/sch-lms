# Контрольная работа: Сервисы интернет-коммуникаций. Сетевой этикет. Стратегии безопасного поведения в Интернете

Интернет коренным образом преобразил способы коммуникации людей. На смену традиционной бумажной почте и междугородным телефонным станциям пришли цифровые сервисы, работающие в режиме реального времени. Однако вместе с колоссальным удобством мгновенного обмена данными глобальная сеть принесла новые угрозы: утечки конфиденциальной информации, кибермошенничество, вредоносное программное обеспечение и социальные манипуляции.

Данный урок систематизирует знания по ключевым коммуникационным службам Интернета, нормам сетевого этикета (нетикета), правилам сохранения персональных данных и правовым нормам Российской Федерации в области информационной безопасности.

## 1. Службы и сервисы интернет-коммуникаций

### 1.1. Понятие коммуникационной службы и архитектура «Клиент — Сервер»
Компьютерная сеть сама по себе представляет лишь физическую инфраструктуру (кабели, маршрутизаторы, радиоканалы) и протоколы передачи пакетов данных. Чтобы пользователи могли общаться, на базе этой инфраструктуры разворачиваются **прикладные службы (сервисы)**.

Подавляющее большинство сетевых сервисов функционирует по модели **«Клиент — Сервер» (Client-Server)**:
* **Сервер (Server):** мощный специализированный компьютер, постоянно подключенный к сети, на котором работает серверное программное обеспечение. Сервер хранит учетные записи, базы сообщений, файлы, обрабатывает запросы клиентов и маршрутизирует потоки данных.
* **Клиент (Client):** программа, установленная на устройстве пользователя (компьютере, смартфоне, планшете), либо веб-страница в браузере. Клиент предоставляет удобный графический интерфейс, формирует запрос к серверу и отображает полученный ответ.

```
 [Устройство пользователя]                 [Сервер службы]
 ┌──────────────────────┐   Запрос (Request)   ┌──────────────────────┐
 │ Клиентское ПО        │ ───────────────────> │ Серверное ПО         │
 │ (Почтовый клиент /   │                      │ (Обработка, проверка │
 │ браузер / мессенджер)│ <─────────────────── │ прав, базы данных)   │
 └──────────────────────┘    Ответ (Response)  └──────────────────────┘
```

### 1.2. Электронная почта (e-mail): принципы работы и структура адреса
**Электронная почта (Electronic mail, e-mail)** — одна из старейших и наиболее надежных служб компьютерных сетей, предназначенная для асинхронного обмена текстовыми сообщениями и прикрепленными файлами между пользователями.

Асинхронность означает, что отправитель и получатель не обязаны находиться в сети одновременно: отправленное письмо сохраняется в электронном почтовом ящике на сервере получателя и ожидает, пока адресат не запросит его загрузку.

#### Структура адреса электронной почты
Каждый почтовый ящик в глобальной сети обладает уникальным адресом, состоящим из двух частей, разделенных символом `@` («собака», официальное англоязычное название — *commercial at*):

> **Формат адреса электронной почты:** `имя_пользователя@имя_почтового_сервера`

* **Имя пользователя (логин / local part):** идентификатор конкретного почтового ящика, зарегистрированный на данном сервере (например, `ivan.ivanov`, `student_2026`, `info`). Регистр букв, как правило, не имеет значения, но в имени допускаются латинские буквы, цифры, точки, дефисы и знаки подчеркивания.
* **Символ `@`:** обязательный разделитель, указывающий, на каком именно сервере размещен данный ящик.
* **Имя почтового сервера (домен):** доменное имя организации или почтовой службы (например, `school7.ru`, `yandex.ru`, `mail.ru`).

Пример корректного адреса: `alexey.petrov@school102.edu.ru`.

### 1.3. Почтовые протоколы: передача и доставка корреспонденции (SMTP, POP3, IMAP)
Передача электронных писем осуществляется с помощью строго стандартизированных сетевых протоколов прикладного уровня:

| Протокол | Название протокола | Назначение и принцип действия | Стандартный порт | Защищенный порт (SSL/TLS) |
| :--- | :--- | :--- | :---: | :---: |
| **SMTP** | *Simple Mail Transfer Protocol* | **Отправка почты.** Используется клиентской программой для отправки письма на свой почтовый сервер, а также для передачи писем между почтовыми серверами в Интернете. Протокол односторонний: он умеет только «толкать» корреспонденцию вперед. | **25**, **587** | **465** (SMTPS) |
| **POP3** | *Post Office Protocol version 3* | **Прием почты (скачивание).** Клиент подключается к серверу, скачивает поступившие письма на локальный жесткий диск и по умолчанию удаляет их с сервера. Подходит для работы на одном постоянном компьютере с медленным или нестабильным интернетом. | **110** | **995** (POP3S) |
| **IMAP** | *Internet Message Access Protocol* | **Синхронизация почты.** Письма постоянно хранятся на сервере, а клиентские программы лишь синхронизируют папки (Входящие, Отправленные, Спам). Прочтение письма на смартфоне мгновенно отмечает его прочитанным на домашнем компьютере. | **143** | **993** (IMAPS) |

#### Веб-интерфейс почты (Webmail)
Большинство современных пользователей читает электронную почту не через специализированные почтовые программы (Thunderbird, Outlook), а через обычный веб-браузер. В этом случае браузер связывается с почтовым сервером по защищенному протоколу **HTTPS** (порт 443), а сам веб-сервер уже взаимодействует с хранилищем писем по протоколам IMAP/SMTP внутри защищенного контура компании.

### 1.4. [Углубленный курс / Технологический профиль]: Внутренняя структура письма (MIME, RFC 5322) и служебные заголовки
Каждое электронное письмо представляет собой текстовый файл определенного формата, состоящий из двух ключевых частей: **служебных заголовков (Headers)** и **тела сообщения (Body)**, разделенных одной пустой строкой.

#### Основные заголовки письма:
* `From:` адрес отправителя (отображаемое имя и фактический ящик).
* `To:` адрес основного получателя (или нескольких получателей через запятую).
* `Subject:` тема сообщения — краткая аннотация содержимого (крайне важный элемент сетевой культуры).
* `Date:` точное время отправки сообщения по часовому поясу UTC.
* `Cc:` (*Carbon Copy* — копия) — открытые адреса вторичных получателей; все участники переписки видят, кому еще отправлена копия.
* `Bcc:` (*Blind Carbon Copy* — скрытая копия) — адреса скрытых получателей. Ни основной адресат (`To`), ни получатели копии (`Cc`) не видят адресов, указанных в поле `Bcc`. Это ключевой инструмент защиты конфиденциальности при массовых рассылках.
* `Reply-To:` адрес для ответа. Если он указан, нажатие кнопки «Ответить» подставит именно этот ящик, даже если письмо пришло с ящика `From`. Злоумышленники часто используют различие между `From` и `Reply-To` в фишинговых атаках.
* `Message-ID:` уникальный глобальный идентификатор письма, генерируемый почтовым сервером отправителя.
* `Received:` цепочка отметок всех серверов-ретрансляторов, через которые проходило письмо по пути от отправителя к получателю. Изучение полей `Received` позволяет установить реальный IP-адрес источника спама или фишинговой рассылки.

#### Стандарт MIME (Multipurpose Internet Mail Extensions)
Изначально электронная почта создавалась для передачи исключительно 7-битного текста на латинице (ASCII). Стандарт **MIME** расширил возможности почты:
1. Позволил использовать нелатинские алфавиты (включая кириллицу) с помощью кодировок UTF-8, Windows-1251 или KOI8-R;
2. Позволил передавать форматированный текст (HTML-разметку);
3. Позволил прикреплять двоичные файлы (изображения, документы, архивы), которые кодируются в текстовый формат алгоритмом **Base64** (каждые 3 байта исходного файла превращаются в 4 текстовых ASCII-символа, что увеличивает объем пересылаемых данных примерно на 33%).

### 1.5. Службы мгновенных сообщений (Instant Messaging) и современные мессенджеры
В отличие от асинхронной электронной почты, **службы мгновенных сообщений (мессенджеры)** ориентированы на квазисинхронный диалог в реальном времени.

#### Эволюция сервисов мгновенных сообщений:
* **IRC (Internet Relay Chat, 1988 г.):** протокол текстовых чатов, где пользователи подключались к каналам (комнатам) по интересам.
* **ICQ (1996 г.):** первая массовая клиентская программа обмена мгновенными сообщениями, использовавшая уникальный цифровой номер пользователя (UIN).
* **Современные мобильные мессенджеры (Telegram, VK Мессенджер, WhatsApp):** привязка аккаунта к номеру телефона, автоматическая синхронизация списка контактов, поддержка групповых чатов, каналов, аудиосообщений, видеозвонков и чат-ботов.

#### Архитектура безопасности: Сквозное шифрование (End-to-End Encryption — E2EE)
В традиционных чатах сообщения передаются на сервер сервиса, расшифровываются там, сохраняются в базе данных и отправляются собеседнику. При наличии судебного ордера или компрометации сервера переписка может стать доступна третьим лицам.

В защищенных чатах используется **сквозное шифрование (E2EE)**:
1. Ключи шифрования и дешифрования генерируются непосредственно на клиентских устройствах пользователей;
2. Сообщение зашифровывается на смартфоне отправителя;
3. Сервер выступает лишь «слепым» ретранслятором зашифрованного цифрового шума — даже владельцы сервиса не могут расшифровать текст;
4. Расшифровка происходит исключительно на смартфоне получателя, владеющего закрытым приватным ключом.

### 1.6. Форумы, телеконференции и социальные сети
Для публичного и группового общения по интересам используются специализированные платформы:

* **Тематические форумы:** веб-ресурсы с четкой древовидной структурой. Пространство разбито на разделы и темы («топики»), внутри которых публикуются посты пользователей. Форумы сохраняют ценные архивы технической и экспертной информации на протяжении десятилетий.
* **Социальные сети (ВКонтакте, Одноклассники и др.):** комплексные платформы, объединяющие профили пользователей, социальные связи («друзья», «подписчики»), новостные ленты, сообщества, мультимедиа-контент и встроенные платежные системы.
* **Модерация:** порядок на форумах и в сетевых сообществах обеспечивают **модераторы** (пользователи с расширенными правами, следящие за соблюдением правил) и **администраторы** (владельцы ресурса).
  * *Премодерация:* сообщение появляется на сайте только после ручной проверки модератором.
  * *Постмодерация:* сообщения публикуются сразу, но при нарушении правил удаляются модератором, а нарушитель блокируется (получает «бан»).

### 1.7. Облачные хранилища данных и совместная работа с документами
**Облачные сервисы (Cloud Services)** переносят хранение файлов и вычислительные мощности с локального компьютера на удаленные серверные фермы (дата-центры).

#### Возможности облачных дисков (Яндекс Диск, Облако Mail.ru):
1. **Резервное копирование:** защита важных документов от поломки жесткого диска или утери смартфона;
2. **Доступ из любой точки мира:** просмотр файлов с любого устройства при наличии учетной записи;
3. **Совместное редактирование в реальном времени:** несколько пользователей одновременно работают над одной презентацией или таблицей;
4. **Разграничение прав доступа:** владелец файла может гибко настроить уровень доступа для сторонних пользователей:
   * *Только чтение (Просмотр):* адресат может читать и скачивать документ, но не вносить правки;
   * *Комментирование:* возможность оставлять замечания на полях без изменения основного текста;
   * *Полный доступ (Редактирование):* право изменять содержимое документа.

### 1.8. IP-телефония и видеоконференцсвязь (VoIP)
**IP-телефония (Voice over IP — VoIP)** — технология передачи голосового сигнала и видеопотока через компьютерные сети по пакетным протоколам.

Принцип действия:
1. Аналоговый звуковой сигнал с микрофона оцифровывается звуковой картой компьютера или процессором смартфона;
2. Голосовой поток сжимается специализированными алгоритмами (кодеками) для экономии сетевого трафика;
3. Данные разбиваются на небольшие IP-пакеты и отправляются адресату по протоколам реального времени (UDP/RTP);
4. На стороне получателя пакеты собираются в непрерывный поток, распаковываются и преобразуются обратно в аналоговый звук через динамики или наушники.

Главное преимущество VoIP перед классической телефонной связью — независимость стоимости соединения от географического расстояния и возможность организации многопользовательских видеоконференций (телемостов, дистанционных уроков).

## 2. Сетевой этикет (Netiquette) и культура цифрового взаимодействия

### 2.1. Что такое сетевой этикет и почему он необходим?
**Сетевой этикет (Netiquette, нетикет)** — негласный свод традиций, рекомендаций и правил вежливости, регламентирующий культуру общения пользователей в Интернете.

В физическом мире при живом диалоге до 70–80% информации передается невербально: через интонацию голоса, мимику лица, жесты и зрительный контакт. В текстовой переписке невербальные сигналы отсутствуют, из-за чего нейтральная фраза может быть легко истолкована собеседником как грубость, насмешка или претензия. Сетевой этикет компенсирует нехватку невербальных сигналов и защищает участников диалога от взаимных конфликтов.

---

### 2.2. Правила ведения личной и деловой электронной переписки
При отправке электронных писем и сообщений в мессенджерах следует соблюдать стандарты цифровой гигиены:

1. **Приветствие и обращение:** любое письмо начинается со слов вежливости («Здравствуйте, уважаемый Иван Сергеевич!», «Добрый день!»). Начинать письмо сразу с требований без приветствия считается признаком невоспитанности.
2. **Обязательное указание темы письма (`Subject`):** тема должна быть емкой и точно отражать суть сообщения (например: *«Реферат по информатике, 7А, Иванов Алексей»* или *«Вопрос по заданию № 5 из параграфа 3.2»*). Письма с пустой темой, темами вроде *«Привет»*, *«Срочно!!!»* или бессмысленным набором букв часто блокируются спам-фильтрами либо игнорируются получателем.
3. **Структурирование текста:** избегайте «стены текста». Разделяйте мысль на логические абзацы (по 3–5 предложений), разделяя их пустыми строками. Используйте маркированные списки при перечислении фактов или вопросов.
4. **Грамотность:** перед отправкой перечитайте сообщение, проверьте орфографию и пунктуацию. Систематические ошибки и отсутствие знаков препинания затрудняют восприятие смысла и демонстрируют неуважение к адресату.
5. **Подпись в конце письма:** деловое письмо должно оканчиваться вежливой формулой и подписью (*«С уважением, ученик 7А класса Алексей Иванов»*).
6. **Осмысленное именование файлов во вложении:** прикрепляемый файл должен иметь понятное имя на латинице или кириллице (например, `Doklad_Seti_Ivanov_7A.docx`, а не `Документ12345.docx` или `scan_001.pdf`).

### 2.3. Тема письма, цитирование и борьба с оверквотингом (Overquoting)
При ответе на входящее письмо почтовая программа автоматически создает копию исходного текста и добавляет префикс `Re:` (*in re* — по поводу) к теме письма.

#### Правило корректного цитирования:
* Цитируйте только те фрагменты чужого сообщения, на которые непосредственно дается ответ.
* Помещайте свой ответ непосредственно под цитируемым блоком, отделяя их строкой.

#### Оверквотинг (Overquoting — избыточное цитирование):
Грубейшим нарушением сетевого этикета является ситуация, когда пользователь оставляет в письме всю предшествующую многомесячную переписку на десятки страниц со всеми служебными заголовками, а в самом низу приписывает одно слово: *«Согласен»* или *«Спасибо»*. Оверквотинг засоряет почтовые ящики, тратит мобильный трафик и затрудняет чтение сути сообщения.

### 2.4. Эмоциональный окрас, смайлики и «синдром Caps Lock»

#### Синдром Caps Lock (ТЕКСТ ЗАГЛАВНЫМИ БУКВАМИ):
В культуре Интернета написание слов или целых предложений заглавными буквами (`CAPS LOCK`) безоговорочно воспринимается как **крик, эмоциональная истерика, агрессия или грубое давление**.
* Использование `CAPS LOCK` допустимо исключительно для аббревиатур (ЭВМ, ОГЭ, URL, ФГОС) либо для акцентирования одного конкретного ключевого слова.
* Написание целых сообщений верхним регистром запрещено правилами практически всех форумов, чатов и игровых серверов.

#### Смайлики и эмодзи:
* В неформальном дружеском общении смайлики (текстовые `:-)` или графические эмодзи) помогают передать улыбку, иронию или грусть.
* В официальной и учебной деловой переписке (письма учителям, обращения в администрацию школы, техническую поддержку) смайлики неуместны либо должны использоваться предельно сдержанно (не более одного нейтрального знака).
* Избыток смайликов делает текст несерьезным, инфантильным и сложным для понимания.

---

### 2.5. Деструктивное поведение в сети: спам, флуд, флейм и троллинг
В сетевых сообществах выработана строгая терминология для обозначения деструктивных паттернов поведения:

```
┌────────────────────────────────────────────────────────────────────────┐
│             ФОРМЫ ДЕСТРУКТИВНОГО ПОВЕДЕНИЯ В СЕТИ                      │
├─────────────────┬─────────────────┬──────────────────┬─────────────────┤
│      СПАМ       │      ФЛУД       │      ФЛЕЙМ       │    ТРОЛЛИНГ     │
│ (Массовая       │ (Бессмысленный  │ (Эмоциональная   │ (Провокация,    │
│  рассылка       │  поток знаков   │  ругань, переход │  разжигание     │
│  рекламы)       │  и сообщений)   │  на личности)    │  конфликтов)    │
└─────────────────┴─────────────────┴──────────────────┴─────────────────┘
```

1. **Спам (Spam):**
   * Массовая нежелательная рассылка коммерческой рекламы, сомнительных предложений, вредоносных ссылок лицам, которые не выражали согласия на их получение.
   * *Историческая справка:* название происходит от консервированного колбасного фарша марки SPAM (*Shoulder Pork and hAM*), агрессивная и навязчивая реклама которого после Второй мировой войны высмеивалась в комедийном скетче группы «Монти Пайтон».
2. **Флуд (Flood — наводнение):**
   * Засорение чатов, комментариев или форумов непрерывным потоком пустых, бессмысленных или повторяющихся сообщений, смайлов, картинок-стикеров или одинаковых символов за короткий промежуток времени. Цель флудера — заполнить экран, парализовать работу канала и не дать другим участникам вести осмысленный диалог.
3. **Флейм (Flame — пламя, вспышка страстей):**
   * Бурный, эмоциональный спор в сети, в ходе которого участники напрочь забывают о предмете разногласий, переходят на взаимные оскорбления, личные нападки и нецензурную лексику.
4. **Троллинг (Trolling):**
   * Публикация провокационных, язвительных, заведомо ложных или абсурдных сообщений с целью вызвать возмущение аудитории, разжечь ссору и выставить собеседников в глупом свете.
   * *Золотое правило сетевого этикета:* **«Не кормите троллей» (Don't feed the trolls)**. Тролль жаждет эмоциональной реакции; полное игнорирование лишает его манипуляцию смысла.

---

### 2.6. Конфиденциальность и тайна частной переписки
Электронная переписка защищена принципом неприкосновенности частной жизни:
* Категорически запрещено публиковать скриншоты чужой личной переписки в социальных сетях или пересылать приватные письма и аудиосообщения другим людям без явного предварительного согласия автора.
* Недопустимо вскрывать чужие электронные почтовые ящики, заглядывать в экран чужого смартфона или читать сообщения за спиной одноклассника.
* Нарушение тайны переписки является не просто аморальным поступком, но и прямым правонарушением, преследуемым по закону.

## 3. Стратегии безопасного поведения в сети Интернет

### 3.1. Персональные данные: состав, ценность и правила неразглашения
**Персональные данные (ПДн)** — любая информация, относящаяся к прямо или косвенно определенному физическому лицу (субъекту персональных данных).

#### Что относится к персональным данным:
* Фамилия, имя и отчество;
* Дата и точное место рождения;
* Домашний адрес и номер домашнего телефона;
* Номер мобильного телефона;
* Номер и наименование школы, номер класса;
* Паспортные данные, номер свидетельства о рождении, СНИЛС, ИНН;
* Фотографии документов (билетов на поезд/самолет, грамот с адресами);
* Данные банковских карт родителей (номер, срок действия, трехзначный CVV/CVC код на обороте);
* Геолокационные метки в реальном времени.

#### Опасность избыточной открытости (Овершеринг — Oversharing):
Публикация в открытых аккаунтах социальных сетей домашнего адреса, распорядка дня (например: *«Ура, мы всей семьей улетели на море на две недели!»*) и дорогих покупок привлекает квартирных воров и мошенников.

> [!IMPORTANT]
> **Железное правило цифровой безопасности:**
> Никогда не публикуйте в публичном доступе и не сообщайте незнакомцам в сети свои паспортные данные, домашний адрес, геолокацию и платежную информацию родителей. Помните: всё, что попало в Интернет, может остаться там навсегда.

---

### 3.2. Цифровой след (Digital Footprint) и цифровая репутация
**Цифровой след (электронный след)** — уникальный набор данных о действиях, активности и перемещениях пользователя, фиксируемый серверами в процессе работы в глобальной сети.

```
                            ЦИФРОВОЙ СЛЕД ПОЛЬЗОВАТЕЛЯ
                                      │
          ┌───────────────────────────┴───────────────────────────┐
          ▼                                                       ▼
   АКТИВНЫЙ СЛЕД                                           ПАССИВНЫЙ СЛЕД
   (Осознанные действия):                                  (Автоматический сбор):
   • Публикации, посты, твиты                              • Внешний IP-адрес узла
   • Фотографии и видеоролики                              • Файлы cookie и токены сессий
   • Комментарии и отзывы                                  • История поисковых запросов
   • Подписки и лайки                                      • Модель устройства и версия ОС
```

* **Активный цифровой след:** информация, которую пользователь сознательно публикует о себе (посты, фото, комментарии, видеозаписи, подписки).
* **Пассивный цифровой след:** технические логи, собираемые сайтами без прямого участия человека (IP-адрес, тип браузера, разрешение экрана, файлы `cookie`, история посещенных страниц, координаты Wi-Fi точек).

#### Цифровая репутация:
Работодатели, приемные комиссии ведущих вузов и служб безопасности при рассмотрении кандидатов обязательно анализируют их цифровой след в социальных сетях. Грубые высказывания, агрессивные комментарии, участие в травле или публикация противоправного контента, совершенные в подростковом возрасте, могут перечеркнуть карьеру через 5–10 лет.

### 3.3. Кибербуллинг и социальные угрозы: распознавание и алгоритм противодействия
**Кибербуллинг (Cyberbullying, интернет-травля)** — систематическое намеренное преследование, запугивание, оскорбление или унижение человека с использованием цифровых технологий (мессенджеров, социальных сетей, форумов, онлайн-игр).

#### Типичные проявления кибербуллинга:
* Отправка оскорбительных, угрожающих личных сообщений;
* Создание специальных групп, каналов или страниц для травли и распространения ложных сплетен;
* Публикация чужих компрометирующих фотографий, личных тайн или поддельных скриншотов переписки;
* Массовый «хейт» (наплыв оскорбительных комментариев под постами жертвы);
* Бойкот в групповых чатах класса (исключение из бесед, игнорирование).

#### Алгоритм безопасных действий при кибербуллинге:
1. **Не отвечать агрессией на агрессию:** буллеры ждут паники, оправданий или ответной ругани. Вступление в спор лишь усиливает травлю.
2. **Зафиксировать доказательства:** сделать четкие скриншоты всех оскорбительных сообщений, постов, комментариев с указанием даты, времени и адресов аккаунтов обидчиков.
3. **Заблокировать агрессора:** внести профили обидчиков в черный список (бан) во всех мессенджерах и соцсетях.
4. **Пожаловаться администрации платформы:** нажать кнопку «Пожаловаться на контент / травлю» для блокировки страницы агрессора.
5. **Обязательно рассказать доверенным взрослым:** не держать проблему в себе; сообщить родителям, классному руководителю, школьному психологу.
6. **Обратиться на специализированные линии помощи:** в России действует бесплатный анонимный Всероссийский телефон доверия для детей, подростков и их родителей: **8-800-2000-122**, а также линия помощи «Дети онлайн»: **8-800-25-000-15**.

#### Груминг и незнакомцы в сети:
**Груминг** — установление взрослым злоумышленником доверительных отношений с ребенком в интернете под видом ровесника или друга с целью личной встречи или манипуляций.
* *Правило безопасности:* если виртуальный знакомый настойчиво расспрашивает о домашнем адресе, доходах семьи, требует прислать интимные фотографии или предлагает встретиться лично без родителей — немедленно прекратите общение и сообщите взрослым!

### 3.4. Фишинг, скам и методы социальной инженерии
Злоумышленникам значительно проще обмануть человека, чем взломать сложный криптографический алгоритм. Использование человеческих слабостей (любопытства, страха, жадности, торопливости) в компьютерной безопасности называют **социальной инженерией**.

#### Фишинг (Phishing — от англ. *fishing* — рыбалка, выуживание):
Вид интернет-мошенничества, цель которого — обманным путем выманить у пользователя его конфиденциальные данные (логины, пароли, коды двухфакторной аутентификации, реквизиты банковских карт).

Злоумышленники создают точные визуальные копии популярных сайтов (социальных сетей, банков, игровых серверов) и заманивают на них пользователей через письма, сообщения в мессенджерах или контекстную рекламу.

```
 ┌──────────────────────────────────────────────────────────────┐
 │                      СХЕМА АТАКИ ФИШИНГА                     │
 ├──────────────────────────────────────────────────────────────┤
 │  1. Мошенник создает сайт-двойник с похожим доменным именем  │
 │  2. Жертве отправляется тревожное сообщение:                 │
 │     «Ваш аккаунт заблокирован! Срочно войдите для отмены!»   │
 │  3. Жертва переходит по ссылке и вводит пароль               │
 │  4. Пароль уходит злоумышленнику, аккаунт захватывается      │
 └──────────────────────────────────────────────────────────────┘
```

#### Признаки фишинговых сообщений и сайтов:
* **Поддельный домен в адресной строке браузера:** мошенники регистрируют имена, отличающиеся от подлинного сайта одной незаметной буквой (тайпосквоттинг), дефисом или доменной зоной:
  * Настоящий сайт: `gosuslugi.ru`
  * Фишинговые ловушки: `gos-uslugi-portal.ru`, `gosuslugi.cc`, `gosuslugii.ru`.
* **Эмоциональное давление и искусственная спешка:** мошенники всегда торопят: *«Осталось 10 минут!», «Срочно подтвердите карту, иначе все средства будут списаны!»*. Спешка отключает критическое мышление.
* **Грамматические ошибки и кривой текст:** шаблонные рассылки часто переводятся автоматическими переводчиками и содержат опечатки.
* **Запрос конфиденциальной информации:** администрация банков и сервисов никогда не просит пользователей прислать пароль или код из SMS.

---

### 3.5. [Углубленный курс / Технологический профиль]: Механизмы фишинговых атак и фальсификации адресов
Продвинутые злоумышленники используют тонкие технические манипуляции для обмана бдительности пользователей:

1. **Атака гомоглифами (IDN Homograph Attack):**
   * Международный стандарт IDN позволяет использовать символы национальных алфавитов в доменных именах (Punycode-преобразование `xn--...`).
   * Буквы латинского алфавита **«a», «c», «e», «o», «p», «x»** визуально неотличимы от соответствующих букв русского алфавита.
   * Злоумышленник может зарегистрировать домен, где буква «o» заменена на русскую «о». Визуально адрес выглядит безупречно (`apple.com`), но в сетевом стеке декодируется как `xn--pple-43d.com` и ведет на вредоносный сервер.
2. **Спуфинг почтового отправителя (Email Spoofing):**
   * Базовый протокол SMTP исторически разрабатывался в доверительной среде и не проверял подлинность поля `From:`.
   * Для защиты от фальсификации адресов современные почтовые серверы используют криптографические стандарты:
     * **SPF (Sender Policy Framework):** DNS-запись, перечисляющая IP-адреса серверов, имеющих право отправлять почту от имени данного домена;
     * **DKIM (DomainKeys Identified Mail):** цифровая подпись письма закрытым ключом домена, проверяемая открытым ключом в DNS;
     * **DMARC:** регламент, указывающий принимающему серверу, как поступать с письмами, провалившими проверку SPF/DKIM (отклонять или отправлять в спам).

### 3.6. Правила создания надежных паролей и двухфакторная аутентификация (2FA)
Пароль — это первый рубеж обороны цифрового аккаунта.

#### Почему пароли взламывают?
* **Метод полного перебора (Brute Force):** программа перебирает все возможные комбинации символов подряд (`aaa`, `aab`, `aac`...).
* **Атака по словарям (Dictionary Attack):** программа подставляет наиболее популярные слова и устойчивые словосочетания.
* **Использование утечек:** злоумышленники берут базы взломанных форумов и проверяют совпадение пар «логин-пароль» на других сервисах.

#### Требования к криптостойкому надежному паролю:
1. **Длина пароля:** не менее **12–14 символов**. Каждый добавленный символ экспоненциально увеличивает время подбора.
2. **Разнообразие символов:** обязательное сочетание символов из четырех независимых групп:
   * строчные буквы (`a-z`, `а-я`);
   * заглавные буквы (`A-Z`, `А-Я`);
   * цифры (`0-9`);
   * специальные знаки (`!`, `@`, `#`, `$`, `%`, `^`, `&`, `*`, `_`, `-`, `?`).
3. **Отсутствие словарных слов и личных данных:** пароль не должен содержать имен, кличек домашних животных, дат рождения, номеров телефонов, городов и популярных фраз.
4. **Уникальность:** для каждого критически важного сервиса (особенно основной электронной почты, Госуслуг и онлайн-банка) должен использоваться **уникальный пароль**. Если один сайт взломают, остальные останутся в безопасности.
5. **Использование менеджеров паролей:** хранить десятки сложных паролей в голове невозможно. Для этого применяются защищенные менеджеры паролей (KeePass, Bitwarden и др.), где все пароли зашифрованы одним главным мастер-паролем.

#### Двухфакторная аутентификация (2FA — Two-Factor Authentication):
Даже самый длинный пароль может быть перехвачен троянской программой или украден через фишинг. 2FA добавляет второй, независимый фактор проверки подлинности:
* **Фактор 1 (Знание):** то, что вы знаете (логин и пароль);
* **Фактор 2 (Владение):** то, чем вы физически владеете (смартфон, на который приходит одноразовый push-код, SMS или генерируется 6-значный TOTP-код в приложении-аутентификаторе Яндекс Ключ / Google Authenticator).

Без доступа к физическому устройству пользователя злоумышленник не сможет проникнуть в аккаунт, даже если знает верный пароль.

---

### 3.7. Безопасность при подключении к общественным сетям Wi-Fi
Бесплатные открытые точки доступа Wi-Fi в кафе, парках, транспорте и торговых центрах таят скрытые угрозы:
* **Отсутствие шифрования трафика:** открытые сети без пароля передают радиосигналы в незашифрованном виде. Любой человек, находящийся неподалеку со специальной программой-сниффером (например, Wireshark), может перехватить незашифрованные данные.
* **Атака «Злой двойник» (Rogue AP / Evil Twin):** мошенник включает переносной роутер с именем, идентичным названию сети кафе (`Free_Cafe_WiFi`). Устройства пользователей автоматически подключаются к поддельной точке доступа, и весь трафик проходит через компьютер мошенника (атака «Человек посередине» — *Man-in-the-Middle*).

#### Правила работы в публичных сетях:
1. Отключить в смартфоне функцию «Автоматическое подключение к открытым сетям Wi-Fi»;
2. Никогда не входить в банковские приложения, Госуслуги и не совершать покупки через публичный Wi-Fi;
3. Для конфиденциальных операций использовать мобильный интернет (3G/4G/5G) своего оператора связи — мобильный радиоканал зашифрован аппаратно;
4. Всегда проверять наличие значка безопасного соединения (замочка) в строке браузера (`https://`).

---

### 3.8. Вредоносные вложения и проверка ссылок перед переходом
Один из главных каналов распространения вирусов, программ-вымогателей (Ransomware) и троянов — вложения в электронной почте и мессенджерах:
* **Опасные расширения файлов:** никогда не открывайте полученные от неизвестных адресатов файлы с расширениями `.exe`, `.bat`, `.cmd`, `.vbs`, `.scr`, `.msi`, `.js`, а также заархивированные файлы (`.zip`, `.rar`, `.7z`), внутри которых прячутся исполняемые файлы.
* **Двойные расширения:** злоумышленники маскируют вирус под документ: `Spisok_literatury.pdf.exe`. Поскольку Windows по умолчанию скрывает расширения для зарегистрированных типов файлов, пользователь видит безобидное название `Spisok_literatury.pdf` и запускает вирус.
* **Макросы в документах Office:** вредоносный код может содержаться в документах с поддержкой макросов (`.docm`, `.xlsm`). Никогда не нажимайте кнопку *«Включить содержимое / Разрешить редактирование»* в документах, пришедших из ненадежных источников.

## 4. Правовые основы информационной безопасности в Российской Федерации

Виртуальное пространство Интернета не является зоной вседозволенности. В Российской Федерации действует строгое законодательство, регулирующее деятельность в цифровой среде и защищающее права граждан.

### 4.1. Федеральный закон № 152-ФЗ «О персональных данных»
Принят 27 июля 2006 года. Закон устанавливает:
* Любая организация (школа, банк, сайт, соцсеть), собирающая данные граждан, признается **оператором персональных данных**;
* Сбор, хранение и обработка данных допускаются только с письменного или электронного согласия гражданина (или его законных представителей — родителей);
* Операторы обязаны принимать технические и организационные меры для защиты баз данных от утечек и неправомерного доступа;
* Гражданин имеет право в любой момент потребовать удаления своих персональных данных.

---

### 4.2. Уголовный кодекс РФ: ответственность за киберпреступления
В Уголовном кодексе РФ (УК РФ) преступлениям в сфере высоких технологий посвящена Глава 28 («Преступления в сфере компьютерной информации»), а также специальные статьи Особенной части:

| Статья УК РФ | Наименование состава преступления | Суть правонарушения | Предусмотренное наказание |
| :--- | :--- | :--- | :--- |
| **Статья 138** | *Нарушение тайны переписки, телефонных переговоров, почтовых, телеграфных или иных сообщений* | Взлом чужого почтового ящика, чтение личных сообщений в мессенджере, прослушивание звонков, публикация чужой конфиденциальной переписки без согласия автора. | Штраф до 80 000 рублей, обязательные или исправительные работы (ч. 1); при использовании служебного положения — лишение свободы до **4 лет** (ч. 2). |
| **Статья 159.6** | *Мошенничество в сфере компьютерной информации* | Хищение чужого имущества или приобретение права на чужое имущество путем ввода, удаления, блокирования, модификации компьютерной информации (фишинг, хищение денег с банковских карт через поддельные платежные шлюзы). | Штраф до 120 000 рублей, принудительные работы, лишение свободы на срок **до 2 лет** (ч. 1); в составе организованной группы или в особо крупном размере — лишение свободы на срок **до 10 лет** (ч. 4). |
| **Статья 272** | *Неправомерный доступ к компьютерной информации* | Несанкционированное проникновение в чужую компьютерную систему, повлекшее уничтожение, блокирование, модификацию либо копирование информации (взлом сайтов, аккаунтов, кража баз данных). | Штраф до 200 000 рублей, принудительные работы либо лишение свободы на срок **до 2 лет** (ч. 1); при тяжких последствиях — лишение свободы на срок **до 7 лет** (ч. 4). |

---

### 4.3. Возраст ответственности и правовая культура школьника
* По общему правилу, уголовная ответственность в Российской Федерации наступает с возраста **16 лет** (статья 20 УК РФ).
* Однако за ряд тяжких преступлений (включая вымогательство, хищение в крупных размерах, террористические угрозы, ложные сообщения о минировании через интернет по ст. 207 УК РФ) ответственность наступает уже с **14 лет**.
* До достижения возраста уголовной ответственности за противоправные действия несовершеннолетних (взлом аккаунтов одноклассников, порчу школьной техники, буллинг с нанесением морального вреда) материальную и гражданско-правовую ответственность несут их **родители или законные представители**, а самого подростка ставят на профилактический учет в Комиссию по делам несовершеннолетних (КДН).

## Дополнительная информация

### Для уровня 1 (Базовый)
На базовом уровне интерактивного тренажера ученик решает пространственно-логические задачи методами физической манипуляции объектами (классификация сетевого контента, сборка защищенного пароля и коммутация сетевых протоколов):

1. **Фаза 1: Сортировка сетевого контента и входящих сообщений (Drag-to-Bucket):**
   * В рабочей области появляются поступающие электронные сообщения, ссылки и системные уведомления. Ученик распределяет их мышью по трем целевым функциональным контейнерам:
     * **Шлюз «Легитимная корреспонденция»:** официальные сообщения от учителей, уведомления с подтвержденных школьных порталов (`.edu.ru`), письма от друзей с корректной темой и без подозрительных вложений.
     * **Шлюз «Спам и деструктив»:** навязчивая реклама онлайн-игр, бессмысленный флуд из сотен восклицательных знаков, эмоциональный капслок, сообщения с агрессивным содержанием.
     * **Шлюз «Киберугрозы и фишинг»:** тревожные требования срочно сменить пароль по ссылке с тайпосквоттингом (например, `vkk-login.ru`), сообщения о неожиданном «выигрыше миллиона», вложенные исполняемые файлы (`.exe`, `.scr`, `.zip`), запросы реквизитов банковских карт родителей.
   * **Метод решения:** внимательно анализируйте адрес отправителя, доменное имя в ссылках, наличие спешки и тему письма перед направлением в шлюз.

2. **Фаза 2: Конструирование безопасного электронного письма и криптостойкого пароля (Slot & Snap):**
   * В первой части фазы собирается структура письма: в правильные слоты перетаскиваются токен адресата (`ivanov@school.ru`), осмысленная тема письма, вежливое обращение и корректная подпись. Лишние блоки (разговорный сленг, пустая тема, капслок) отсекаются в палитру дистракторов.
   * Во второй части фазы конструируется криптостойкий пароль: в целевые гнезда укладываются символы из обязательных групп (строчные буквы, заглавные буквы, цифры, спецсимволы `!@#$`), обеспечивая общую длину не менее 12 символов. Простые словарные слова (`password`, `qwerty123`, `2012`) отбрасываются.
   * **Метод решения:** следите за разнообразием категорий символов в пароле и соответствием международным стандартам безопасности.

3. **Фаза 3: Интерактивная коммутация сетевых протоколов и уровней защиты (Node Linking):**
   * Ученик соединяет соединительными кабелями прикладные коммуникационные протоколы и их защищенные стандарты связи:
     * Отправка электронной почты по закрытому каналу: `SMTP` ➔ порт `465` (SMTPS);
     * Скачивание почты на один компьютер: `POP3` ➔ порт `995` (POP3S);
     * Синхронизация почты на всех мобильных устройствах: `IMAP` ➔ порт `993` (IMAPS);
     * Защита от перехвата в общественном Wi-Fi: клиентский трафик ➔ зашифрованный туннель `VPN` или протокол `HTTPS`.
   * **Метод решения:** сопоставляйте функциональное назначение службы с её эталонным криптографическим портом.

### Для уровня 2 (Продвинутый)
На продвинутом уровне исключены визуальные подсказки; требуется самостоятельный аналитический расчет, синтаксический аудит сетевых данных и ручной ввод ответов в поле ввода (буфер обмена заблокирован):

1. **Фаза 1: Расчет мощности алфавита и энтропии парольной защиты:**
   * Общее количество уникальных комбинаций пароля рассчитывается по комбинаторной формуле:
     
     **N = A<sup>L</sup>**

     где:
     * **A** — мощность используемого алфавита символов;
     * **L** — длина пароля (количество позиций).
   * **Мощности стандартных наборов символов:**
     * Только цифры (`0-9`): **A = 10**;
     * Только строчные латинские буквы (`a-z`): **A = 26**;
     * Строчные и прописные латинские буквы (`a-z` + `A-Z`): **A = 26 + 26 = 52**;
     * Буквы обоих регистров + цифры: **A = 52 + 10 = 62**;
     * Полный набор (буквы обоих регистров, цифры и 10 спецзнаков): **A = 62 + 10 = 72**.
   * **Метод расчета:** внимательно определите набор разрешенных символов, сложите мощности групп и возведите полученную сумму в степень длины пароля.

2. **Фаза 2: Анализ сетевых портов и прикладных коммуникационных протоколов:**
   * Ввод стандартных и защищенных номеров портов IANA для почтовых и веб-сервисов:
     * Защищенный веб-протокол передачи гипертекста: **443** (HTTPS);
     * Незащищенный веб-порт: **80** (HTTP);
     * Отправка корреспонденции (SMTP по умолчанию): **25** или резервный **587**;
     * Защищенная отправка корреспонденции (SMTPS): **465**;
     * Протокол доступа к сообщениям без синхронизации (POP3): **110** (защищенный POP3S: **995**);
     * Синхронизация почтовых ящиков (IMAP): **143** (защищенный IMAPS: **993**).

3. **Фаза 3: [Пик 1] Инверсный анализ служебных заголовков электронной почты (RFC):**
   * Ученику предъявляется реальный фрагмент сырых заголовков поступившего письма.
   * Задача: определить истинный сервер отправления по первому снизу полю `Received: from`, выявить несовпадение поля отображаемого отправителя `From:` и адреса возврата `Return-Path:` / `Reply-To:`, либо указать номер статьи УК РФ при обнаружении признаков взлома.

4. **Фаза 4: [Долина консолидации] Синтаксический аудит подозрительных URL и фишинговых маркеров:**
   * Анализ текстовой строки адреса сайта для выявления фишинговых аномалий:
     * поиск дефисов и поддоменов третьего уровня в ложных адресах (например, `sberbank.id-security-auth.ru` — домен 2-го уровня здесь `id-security-auth.ru`, а не `sberbank.ru`);
     * обнаружение замен латинских букв схожими цифрами (`schoo1.ru` вместо `school.ru`);
     * подсчет количества символов в домене второго уровня.

5. **Фаза 5: [Кульминационный пик] Квалификация киберинцидентов по статьям законодательства РФ:**
   * Решение юридических кейсов по защите информации:
     * несанкционированное копирование чужой переписки и взлом почтового аккаунта одноклассника — **Статья 138 УК РФ** и **Статья 272 УК РФ**;
     * рассылка фишинговых писем от имени банка и хищение денежных средств с банковского счета — **Статья 159.6 УК РФ**;
     * сбор и распространение базы личных телефонов и адресов школьников без их согласия — нарушение Федерального закона **№ 152-ФЗ**.

### Для уровня 3 (Аркада)
На аркадном уровне развернут **Архетип 9 («Active Firewall Interceptor / Магистральный щит коммуникаций»)** на декларативном реактивном стеке Vue 3.

Ученик выступает в роли диспетчера сетевого экрана (брандмауэра), защищающего коммуникационный шлюз школы от входящего шквала сетевых пакетов в течение **10 нарастающих волн** под давлением жесткого таймера (от 6.5 секунд на 1-й волне до 3.5 секунд на 10-й волне):

```
       ПОТОК ВХОДЯЩИХ КОММУНИКАЦИОННЫХ ПАКЕТОВ
     [Запрос: Заголовок, Порт, Протокол, Содержимое]
                          │
                          ▼
 ┌──────────────────────────────────────────────────┐
 │       ПАНЕЛЬ АКТИВНОЙ ФИЛЬТРАЦИИ БРАНДМАУЭРА     │
 │       [ПРОПУСТИТЬ]      [БЛОКИРОВАТЬ / SINKHOLE] │
 └────────────────────────┬─────────────────────────┘
                          │
         ┌────────────────┴────────────────┐
         ▼                                 ▼
   ВНУТРЕННЯЯ СЕТЬ                 ИЗОЛЯТОР УГРОЗ
   (Легитимный трафик)             (Фишинг, спам, взлом)
   • HTTPS (порт 443)              • Поддельные заголовки From != Reply-To
   • IMAPS (порт 993)              • Открытый Wi-Fi перехват
   • SMTPS (порт 465)              • Несоответствие портов (SMTP на 110)
   • Проверенные школьные адреса   • Фишинговые ссылки с гомоглифами
```

1. **Правила фильтрации сетевых пакетов:**
   * **Зеленый коридор (ПРОПУСТИТЬ):** легитимные соединения с корректными связками протокола и порта (HTTPS: 443, SMTPS: 465, IMAPS: 993), корректные SPF/DKIM подписи, запросы к проверенным национальным доменам `.ru` и `.рф`.
   * **Красный коридор (БЛОКИРОВАТЬ):**
     * фишинговые адреса с опечатками и поддоменами-ловушками;
     * попытки передачи паролей в открытом виде по незащищенному протоколу HTTP (порт 80);
     * письма с опасными исполняемыми вложениями (`.exe`, `.scr`, `.vbs`);
     * несовпадение заявленного протокола и порта (например, SMTP-трафик на порт 110).

2. **Механика прямого манипулирования и ритм:**
   * Выбор решения осуществляется кликом по кнопкам фильтрации либо горячими клавишами на клавиатуре: **`Стрелка Влево` / `A`** — ПРОПУСТИТЬ, **`Стрелка Вправо` / `D`** — БЛОКИРОВАТЬ.
   * При правильной фильтрации начисляются очки, запускается короткий спецэффект (150 мс) и активируется следующая волна с ускоренным таймером.

3. **Хардкорный сброс (Hardcore Reset):**
   * Пропуск хотя бы одного фишингового пакета во внутреннюю сеть,
   * Ошибочная блокировка легитимного сообщения учителя,
   * Истечение времени таймера текущей волны,
   * → Мгновенно активирует тревожную сирену, отправляет телеметрию `hardcore_reset` и **сбрасывает весь прогресс на Волну 1** с процедурной перегенерацией всего набора пакетов!
