# 📚 Словари (ассоциативные массивы, отображения). Хэш-таблицы. Построение алфавитно-частотного словаря

В курсе информатики 10–11 классов технологического профиля вы подробно изучали классические статические и динамические структуры данных: одномерные и двумерные массивы, динамические списки, стеки и очереди. Главная особенность этих структур — **позиционная адресация**: каждый элемент идентифицируется целочисленным индексом (номером позиции `0, 1, 2, ..., N-1`).

Однако в прикладном программировании, обработке текстов, реляционных СУБД и веб-разработке колоссальное число задач требует адресации данных не по порядковому номеру, а по их смысловому содержанию:
- Найти номер телефона по фамилии абонента;
- Получить IP-адрес сетевого узла по его доменному имени (служба DNS);
- Подсчитать количество повторений каждого слова в художественном произведении;
- Получить координаты и характеристики персонажа игры по его уникальному строковому псевдониму.

Для эффективного решения такого класса задач используется фундаментальный абстрактный тип данных — <span data-term="ассоциативный массив" data-definition="Абстрактный тип данных, хранящий пары ключ-значение с уникальными ключами">ассоциативный массив</span> (также называемый словарем, отображением, картой или `map`/`dict`).

---

## 1. Концепция ассоциативного массива (словаря, отображения)

### 1.1. Математическая модель и сущность отображения
С математической точки зрения ассоциативный массив представляет собой дискретное **отображение (функцию)** из множества ключей `K` во множество значений `V`:

`f: K → V`

Каждый элемент словаря состоит из пары `(ключ, значение)`:
- **Ключ (`Key`):** служит уникальным идентификатором записи. В рамках одного словаря все ключи обязаны быть строго уникальными (дубликаты ключей запрещены). Попытка записи нового значения по уже существующему ключу приводит к перезаписи (обновлению) старого значения.
- **Значение (`Value`):** ассоциированные с ключом полезные данные любого типа (число, строка, список, другой словарь или сложный объект). В отличие от ключей, значения не обязаны быть уникальными: различные ключи могут указывать на одинаковые значения.

```
       МНОЖЕСТВО КЛЮЧЕЙ (K)                    МНОЖЕСТВО ЗНАЧЕНИЙ (V)
       [Уникальные, неизменяемые]              [Произвольные данные]

       ┌────────────────────┐                  ┌────────────────────┐
       │   "router_msk"     │ ────────────────>│   "192.168.1.1"    │
       │   "switch_spb"     │ ────────────────>│   "192.168.1.2"    │
       │   "backup_srv"     │ ────────────────>│   "192.168.1.1"    │ ◄── Значения могут совпадать
       │   "core_gw"        │ ────────────────>│   "10.0.0.254"     │
       └────────────────────┘                  └────────────────────┘
```

### 1.2. Базовые операции абстрактного типа данных
Полноценный интерфейс ассоциативного массива включает следующие фундаментальные операции:
1. **Вставка / обновление (`insert` / `set`):** `dict[key] = value` — связывает ключ со значением. Если ключ отсутствовал, создается новая пара; если существовал, его значение обновляется.
2. **Поиск по ключу (`get` / `find`):** `value = dict[key]` — возвращает значение, сопоставленное заданному ключу. Если ключ отсутствует, генерируется ошибка (исключение `KeyError` в Python) либо возвращается специальное значение (`std::end` в C++, `None`).
3. **Удаление (`delete` / `erase`):** `del dict[key]` — удаляет пару `(ключ, значение)` из структуры данных.
4. **Проверка наличия ключа (`contains`):** `key in dict` — булева проверка факта присутствия ключа в словаре без возбуждения исключений.
5. **Определение размера (`size` / `len`):** `len(dict)` — возвращает текущее количество уникальных ключей в словаре.

## 2. Способы реализации ассоциативных массивов и их вычислительная сложность

В зависимости от требований к производительности и сохранению порядка ключей ассоциативные массивы реализуются в библиотеках языков программирования несколькими принципиально различными способами.

### 2.1. Наивные структуры данных: списки и массивы
1. **Несортированный массив пар:**
   - Новые пары добавляются в конец за время `O(1)`.
   - Поиск ключа и удаление требуют полного линейного перебора всех записей: сложность `O(N)`. При объеме словаря в сотни тысяч записей такой подход катастрофически медленный.
2. **Отсортированный массив пар:**
   - Поиск ключа выполняется бинарным поиском за логарифмическое время `O(log N)`.
   - Однако вставка нового элемента и удаление требуют физического сдвига элементов массива в памяти: сложность `O(N)`.

### 2.2. Сбалансированные бинарные деревья поиска
Ассоциативный массив можно организовать на базе сбалансированного бинарного дерева поиска (красно-черного дерева или АВЛ-дерева).
- Каждый узел дерева хранит пару `(ключ, значение)`.
- Для всех узлов поддерживается инвариант порядка: ключи в левом поддереве строго меньше ключа узла, а в правом — строго больше.
- **Вычислительная сложность:** Поиск, вставка и удаление выполняются за гарантированное время `O(log N)` как в среднем, так и в худшем случае.
- **Главное преимущество:** Элементы всегда хранятся в отсортированном по ключам порядке, что позволяет мгновенно выполнять диапазонные запросы (найти все ключи от `A` до `B`).
- **Языковая реализация:** Контейнер `std::map` в C++, `TreeMap` в Java.

### 2.3. Хэш-таблицы (прямой доступ)
Наиболее эффективным способом реализации ассоциативного массива на практике является <span data-term="хэш-таблица" data-definition="Структура данных, реализующая ассоциативный массив через прямое вычисление индексов хэш-функцией">хэш-таблица</span>.
- Ключ преобразуется специальным алгоритмом напрямую в целочисленный индекс базового массива.
- **Вычислительная сложность:** В среднем поиск, добавление и удаление выполняются за феноменальное константное время `O(1)`.
- **Языковая реализация:** Тип `dict` в Python, контейнер `std::unordered_map` в C++, `HashMap` в Java.

#### Сравнительная таблица вычислительной сложности реализаций:
| Способ реализации | Поиск (в среднем) | Вставка (в среднем) | Удаление (в среднем) | Худший случай (поиск) | Упорядоченность ключей |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Несортированный массив** | `O(N)` | `O(1)` | `O(N)` | `O(N)` | Нет |
| **Отсортированный массив** | `O(log N)` | `O(N)` | `O(N)` | `O(N)` | Да (по ключу) |
| **Бинарное дерево (`std::map`)** | `O(log N)` | `O(log N)` | `O(log N)` | `O(log N)` | Да (по ключу) |
| **Хэш-таблица (`dict`, `unordered_map`)** | `O(1)` | `O(1)` | `O(1)` | `O(N)` | Нет (произвольный) |

## 3. Математические основы хэширования

### 3.1. Принцип работы хэш-функции
Основой функционирования любой хэш-таблицы является <span data-term="хэш-функция" data-definition="Функция, преобразующая входные данные произвольного размера в числовое значение фиксированной длины">хэш-функция</span>.

> **Определение:** Хэш-функция — это математический алгоритм `h(k)`, который преобразует ключ `k` произвольного типа и длины (строку, число, кортеж) в целое неотрицательное число фиксированной разрядности (хэш-код).

Чтобы превратить хэш-код в валидный индекс ячейки массива фиксированной длины `M`, применяется операция взятия остатка от деления:

`index = h(k) mod M`

```
 [ КЛЮЧ k ] ────► [ ХЭШ-ФУНКЦИЯ h(k) ] ────► [ ХЭШ-КОД ] ────► [ mod M ] ────► [ ИНДЕКС В ТАБЛИЦЕ ]
  "apple"              hash("apple")            4829104           mod 8                 0
  "banana"             hash("banana")           7219531           mod 8                 3
  "cherry"             hash("cherry")           1904258           mod 8                 2
```

### 3.2. Требования к качественной хэш-функции
Для обеспечения максимального быстродействия хэш-таблицы хэш-функция обязана удовлетворять следующим строгим инженерным критериям:
1. **Детерминированность:** Для одного и того же входного ключа функция обязана всегда возвращать строго идентичный результат.
2. **Равномерность распределения:** Значения хэш-функции должны распределяться по диапазону `[0; M - 1]` максимально равномерно, без локальных скоплений.
3. **Высокая скорость вычисления:** Время вычисления хэша должно быть пропорционально только размеру самого ключа `O(|k|)` и не зависеть от общего числа элементов в таблице.
4. **Лавинный эффект:** Минимальное изменение входного ключа (например, изменение одного символа или одного бита) должно приводить к кардинальному изменению всех битов результирующего хэш-кода.

### 3.3. Примеры алгоритмов хэширования строк
Для строковых ключей широко применяется **полиномиальное хэширование**. Строка `s` длины `L` рассматривается как коэффициенты полинома от основания `p`:

`h(s) = (s[0] · p<sup>0</sup> + s[1] · p<sup>1</sup> + s[2] · p<sup>2</sup> + ... + s[L-1] · p<sup>L-1</sup>) mod M`

Для исключения переполнения и быстрого последовательного вычисления полином преобразуется по **схеме Горнера**:

```python
def polynomial_hash(s: str, p: int = 31, M: int = 1_000_000_007) -> int:
    h = 0
    for char in s:
        # ord(char) возвращает целочисленный код символа в Unicode
        h = (h * p + ord(char)) % M
    return h
```

### 3.4. Неизбежность коллизий (Принцип Дирихле)
Пусть множество возможных ключей `K` содержит все мыслимые строки длиной до 20 символов (их количество превосходит `10<sup>30</sup>`), а размер хэш-таблицы в оперативной памяти равен `M = 1 000 000` ячеек.

Согласно фундаментальному **принципу Дирихле (Pigeonhole Principle)**: если число кроликов строго больше числа клеток, то хотя бы в одной клетке окажется более одного кролика. Следовательно, неизбежно возникнут различные ключи `k<sub>1</sub> ≠ k<sub>2</sub>`, для которых:

`h(k<sub>1</sub>) mod M == h(k<sub>2</sub>) mod M`

Такая ситуация называется <span data-term="коллизия хэширования" data-definition="Ситуация равенства значений хэш-функции для двух различных исходных ключей">коллизией хэширования</span>. Проектирование структур данных ассоциативных массивов целиком строится вокруг алгоритмов эффективного разрешения коллизий.

## 4. Методы разрешения коллизий в хэш-таблицах

Существуют две основные архитектурные стратегии разрешения коллизий: **метод цепочек** (открытое хэширование) и **открытая адресация** (закрытое хэширование).

### 4.1. Метод цепочек (Separate Chaining)
При использовании <span data-term="метод цепочек" data-definition="Способ разрешения коллизий путем организации связных списков элементов в ячейках таблицы">метода цепочек</span> каждая ячейка хэш-таблицы представляет собой указатель на связный список (или динамический массив) всех записей, хэши ключей которых совпали.

```
 Индекс     Корзина (Bucket)
 ┌───┐
 │ 0 │ ───► [ ("apple", 15) ] ───► [ ("orange", 42) ] ───► [ ("melon", 7) ] ───||
 ├───┤
 │ 1 │ ───► ∅ (пусто)
 ├───┤
 │ 2 │ ───► [ ("cherry", 8) ] ───||
 ├───┤
 │ 3 │ ───► [ ("banana", 23) ] ───► [ ("peach", 99) ] ───||
 └───┘
```

**Алгоритм работы:**
- **Вставка:** Вычисляется индекс `idx = h(key) mod M`. В списке ячейки `idx` выполняется линейный поиск ключа `key`. Если ключ найден, его значение обновляется. Если не найден, новая пара добавляется в список.
- **Поиск:** Вычисляется `idx = h(key) mod M`. Просматривается только список в ячейке `idx`. Если ключ совпал, возвращается значение.
- **Удаление:** Элемент удаляется из связного списка ячейки за время, пропорциональное длине этого конкретного списка.

**Достоинства:** Таблица никогда не переполняется физически (может вместить больше элементов, чем `M`), простая логика удаления элементов.  
**Недостатки:** Дополнительные накладные расходы оперативной памяти на указатели списков, разрозненное расположение узлов в памяти (Cache Misses).

### 4.2. Метод открытой адресации (Open Addressing)
При использовании <span data-term="открытая адресация" data-definition="Способ разрешения коллизий путем последовательного поиска свободной ячейки по фиксированному правилу">открытой адресации</span> все элементы хранятся непосредственно в ячейках самого массива таблицы (одна ячейка — строго один элемент).

Если при вставке целевая ячейка `h(k) mod M` оказывается занятой другим ключом, алгоритм начинает исследование (пробирование, зондирование) таблицы по строгому математическому правилу до первой пустой ячейки:

1. **Линейное пробирование (Linear Probing):**  
   Исследуются ячейки последовательно с шагом 1:
   `idx<sub>i</sub> = (h(k) + i) mod M`, где `i = 0, 1, 2, ...`
   *Недостаток:* Эффект **первичной кластеризации** (Primary Clustering) — занятые ячейки сливаются в длинные непрерывные блоки, что резко замедляет последующий поиск.
2. **Квадратичное пробирование (Quadratic Probing):**  
   Шаг исследования увеличивается квадратично:
   `idx<sub>i</sub> = (h(k) + c<sub>1</sub> · i + c<sub>2</sub> · i<sup>2</sup>) mod M`
   Устраняет первичную кластеризацию, уменьшая вероятность скопления записей.
3. **Двойное хэширование (Double Hashing):**  
   Шаг пробирования определяется второй независимой хэш-функцией `h<sub>2</sub>(k)`:
   `idx<sub>i</sub> = (h<sub>1</sub>(k) + i · h<sub>2</sub>(k)) mod M`
   Наиболее устойчивый метод открытой адресации с отличным распределением.

> [!WARNING]
> **Особенность удаления при открытой адресации:**  
> Ячейку с удаленным элементом нельзя просто очистить (записать `null`), иначе цепочка поиска для других элементов, исследовавших эту позицию ранее, окажется разорванной! Вместо очистки в ячейку помещается специальный маркер — **«надгробие» (tombstone / deleted)**. При поиске алгоритм пропускает «надгробия», а при вставке нового элемента имеет право занять такую ячейку.

### 4.3. Коэффициент заполнения и процедура рехэширования
Эффективность любой хэш-таблицы напрямую зависит от степени ее заполненности. Для контроля используется <span data-term="коэффициент заполнения" data-definition="Отношение числа хранящихся в хэш-таблице элементов к ее общей емкости">коэффициент заполнения</span> (Load Factor, обозначается греческой буквой `α`):

`α = N / M`

где `N` — текущее количество хранящихся элементов, `M` — общее число ячеек хэш-таблицы.

- В хэш-таблицах с открытой адресацией `α` физически не может превышать 1.0 (обычно критическим порогом считается `α ≥ 0.70 ... 0.75`).
- В хэш-таблицах с методом цепочек `α` может превышать 1.0, но при `α > 1` средняя длина цепочек растет, и время операций начинает стремиться к линейному `O(N)`.

Когда коэффициент заполнения превышает допустимый порог, автоматически запускается процедура <span data-term="рехэширование" data-definition="Процедура увеличения размера хэш-таблицы и полного перераспределения элементов при критическом заполнении">рехэширования</span>:
1. Выделяется новый блок непрерывной памяти вдвое большего размера (`M<sub>new</sub> ≈ 2 · M<sub>old</sub>`, предпочтительно простое число).
2. Для каждого существующего ключа заново вычисляется индекс в новой таблице: `new_index = h(k) mod M<sub>new</sub>`.
3. Все элементы перемещаются в новую таблицу, а старый массив освобождается.

Несмотря на то, что само рехэширование требует времени `O(N)`, оно происходит экспоненциально редко. Поэтому **амортизированная вычислительная сложность** добавления элемента в словарь остается строго `O(1)`.

## 5. Словари в современных языках программирования: Python и C++

### 5.1. Устройство словарей в Python (`dict`)
В языке Python словарь является базовой встроенной структурой данных.
- **Требование к ключам:** Ключом словаря может быть только объект неизменяемого типа, реализующий протокол хэширования (`__hash__()` и `__eq__()`). Целые числа, вещественные числа, строки, булевы значения и кортежи из неизменяемых элементов являются хэшируемыми (hashable). Списки, множества и другие словари использовать в качестве ключей запрещено.
- **Внутреннее устройство (PEP 468, CPython 3.6+):** Современный `dict` в Python использует оптимизированную структуру из двух массивов:
  1. Разреженная таблица хэшей (хранит только небольшие индексы смещения);
  2. Компактный плотный массив записей (хранит структуры `[hash, key_ptr, value_ptr]` в порядке их добавления).
  Это инженерное решение сократило потребление памяти на 20–25% и гарантирует, что **словарь в Python всегда сохраняет порядок вставки ключей**.

#### Удобные приемы работы со словарями в Python:
```python
# 1. Безопасное чтение с дефолтным значением через .get()
counter = {}
word = "algorithm"
counter[word] = counter.get(word, 0) + 1

# 2. Использование collections.defaultdict
from collections import defaultdict
freq_dict = defaultdict(int)
freq_dict["matrix"] += 1  # Ключ автоматически инициализируется нулем при первом обращении

# 3. Использование collections.Counter
from collections import Counter
words = ["data", "code", "data", "test", "code", "data"]
freq = Counter(words)
print(freq.most_common(2))  # [('data', 3), ('code', 2)]
```

### 5.2. Ассоциативные контейнеры в C++ (`std::map` и `std::unordered_map`)
В стандартной библиотеке шаблонов (STL) языка C++ представлены обе архитектурные концепции:

| Характеристика | `std::map<Key, Value>` | `std::unordered_map<Key, Value>` |
| :--- | :--- | :--- |
| **Базовая структура данных** | Красно-черное дерево (Red-Black Tree) | Хэш-таблица (метод цепочек) |
| **Сложность поиска / вставки** | Строго `O(log N)` | В среднем `O(1)`, в худшем `O(N)` |
| **Порядок обхода элементов** | Строго по возрастанию ключей (`operator<`) | Произвольный порядок |
| **Требования к типу ключа** | Наличие оператора сравнения `<` | Наличие `std::hash<Key>` и оператора `==` |

## 6. Алгоритм построения алфавитно-частотного словаря текста

Классической задачей на применение словарей в школьном и профильном курсе информатики, а также в задачах компьютерного анализа текста (NLP) является построение алфавитно-частотного словаря.

> **Определение:** <span data-term="алфавитно-частотный словарь" data-definition="Структура данных со списком слов текста и частотой их встречаемости с лексикографической сортировкой">Алфавитно-частотный словарь</span> — это упорядоченный список всех уникальных слов, входящих в исходный текст, с указанием абсолютного количества (или относительной доли) вхождений каждого слова.

### 6.1. Полный пайплайн обработки текста
Процесс построения словаря состоит из четырех последовательных этапов:
1. **Нормализация текста:** Приведение всех символов к единому регистру (обычно к нижнему: `"Строка".lower()`), чтобы слова `"Алгоритм"`, `"алгоритм"` и `"АЛГОРИТМ"` воспринимались как одна лексема.
2. **<span data-term="токенизация" data-definition="Процесс сегментации входного текста на элементарные неделимые лексемы или слова">Токенизация</span>:** Процесс выделения непрерывных последовательностей букв (слов) с игнорированием знаков пунктуации, цифр, пробелов и специальных символов перевода строки.
3. **Аккумуляция в хэш-таблице:** Однократный проход по массиву токенов с инкрементом счетчика для каждого встреченного слова.
4. **Сортировка результатов:**
   - **Алфавитный словарь:** Сортировка пар по возрастанию ключа (лексикографический порядок).
   - **Частотный словарь:** Сортировка по убыванию абсолютной частоты. При равенстве частот слова сортируются по алфавиту (двухуровневая сортировка).

```
   ИСХОДНЫЙ ТЕКСТ: "Хэш, хэш! Таблица и хэш; таблица."
          │
          ▼ [1. Нормализация] (Нижний регистр)
   "хэш, хэш! таблица и хэш; таблица."
          │
          ▼ [2. Токенизация] (Фильтрация пунктуации)
   ["хэш", "хэш", "таблица", "и", "хэш", "таблица"]
          │
          ▼ [3. Подсчет через ассоциативный массив / хэш-таблицу]
   {"хэш": 3, "таблица": 2, "и": 1}
          │
          ├─────────────────────────────────────────┐
          ▼ [4А. Сортировка по алфавиту]            ▼ [4Б. Сортировка по частоте (убывание)]
   "и": 1                                    "хэш": 3
   "таблица": 2                              "таблица": 2
   "хэш": 3                                  "и": 1
```

### 6.2. Эталонная реализация на языке Python
Ниже представлен академически чистый скрипт, выполняющий полный цикл построения алфавитно-частотного словаря без сторонних библиотек:

```python
import string

def build_frequency_dictionary(raw_text: str):
    # Шаг 1: Нормализация и очистка текста от знаков пунктуации
    # Заменяем все знаки препинания на пробелы
    translator = str.maketrans(string.punctuation, " " * len(string.punctuation))
    clean_text = raw_text.translate(translator).lower()
    
    # Шаг 2: Токенизация — разбиение по пробельным символам
    tokens = clean_text.split()
    
    # Шаг 3: Подсчет частот с помощью словаря (хэш-таблицы)
    frequency_map = {}
    for word in tokens:
        frequency_map[word] = frequency_map.get(word, 0) + 1
        
    # Шаг 4А: Алфавитный словарь (сортировка по ключам в лексикографическом порядке)
    alphabetical_order = sorted(frequency_map.items(), key=lambda pair: pair[0])
    
    # Шаг 4Б: Частотный словарь (по убыванию частоты, при равенстве — по алфавиту)
    # Кортеж (-pair[1], pair[0]) реализует двухкритериальную сортировку:
    # 1) -pair[1] — по убыванию частоты (число инвертируется);
    # 2) pair[0] — по возрастанию слова в алфавитном порядке.
    frequency_order = sorted(frequency_map.items(), key=lambda pair: (-pair[1], pair[0]))
    
    return frequency_map, alphabetical_order, frequency_order

# Демонстрация работы алгоритма
sample_text = """
Словари и хэш-таблицы — основа быстрых алгоритмов.
Хэш-таблица обеспечивает поиск за O(1), а словарь связывает ключ и значение!
Быстрый поиск, эффективные алгоритмы и надежные структуры данных.
"""

freq_map, by_alpha, by_freq = build_frequency_dictionary(sample_text)

print("=== ТОП-5 САМЫХ ЧАСТЫХ СЛОВ ===")
for word, count in by_freq[:5]:
    print(f"{word:<15} : {count} раз(а)")
```

### 6.3. Эталонная реализация на языке C++
Для профильных классов и подготовки к олимпиадному программированию полезно рассмотреть реализацию на языке C++ с использованием `std::unordered_map` и вектора пар для сортировки:

```cpp
#include <iostream>
#include <string>
#include <sstream>
#include <vector>
#include <unordered_map>
#include <algorithm>
#include <cctype>

// Функция нормализации строки: удаление пунктуации и перевод в нижний регистр
std::string cleanWord(const std::string& token) {
    std::string result = "";
    for (char c : token) {
        if (!std::ispunct(static_cast<unsigned char>(c))) {
            result += static_cast<char>(std::tolower(static_cast<unsigned char>(c)));
        }
    }
    return result;
}

int main() {
    std::string text = "Hash tables provide fast access. Fast access and hash tables are vital.";
    std::stringstream ss(text);
    std::string rawToken;
    
    // Хэш-таблица для накопления частот: средняя вставка O(1)
    std::unordered_map<std::string, int> frequencyMap;
    
    while (ss >> rawToken) {
        std::string cleaned = cleanWord(rawToken);
        if (!cleaned.empty()) {
            frequencyMap[cleaned]++;
        }
    }
    
    // Копируем пары в вектор для последующей сортировки
    std::vector<std::pair<std::string, int>> items(frequencyMap.begin(), frequencyMap.end());
    
    // Двухкритериальная сортировка: по убыванию частоты, затем по алфавиту
    std::sort(items.begin(), items.end(), [](const auto& a, const auto& b) {
        if (a.second != b.second) {
            return a.second > b.second; // По убыванию частоты
        }
        return a.first < b.first;       // По алфавиту при равной частоте
    });
    
    std::cout << "Частотный словарь:\n";
    for (const auto& [word, count] : items) {
        std::cout << word << ": " << count << "\n";
    }
    
    return 0;
}
```

### 6.4. Анализ вычислительной сложности алгоритма
Оценим временную сложность работы алгоритма:
- Пусть входной текст имеет общую длину `L` символов. Нормализация и токенизация требуют ровно одного прохода: `O(L)`.
- Пусть в тексте выделено `N` слов, из которых `U` слов являются уникальными (`U ≤ N`).
- Вставка каждого слова в хэш-таблицу выполняется за константное время `O(1)` (с учетом средней длины слова `k` — за `O(k)`). Заполнение всей таблицы занимает `O(N · k)`.
- Сортировка `U` уникальных слов требует времени `O(U · log U · k)`.
- **Итоговая временная сложность:** `O(L + U · log U)`. Поскольку в естественном языке число уникальных слов `U` на порядки меньше общего объема текста `L` (закон Ципфа), построение словаря с хэш-таблицей выполняется практически мгновенно даже для текстов объемом в миллионы символов.
- **Емкостная сложность (память):** `O(U · k)` — память требуется только для хранения уникальных слов и их целочисленных счетчиков.

## 7. Практические применения частотных словарей и ассоциативных массивов

Построение алфавитно-частотных словарей лежит в фундаменте множества ключевых информационных технологий:

### 7.1. Сжатие данных: Алгоритм Хаффмана
При статистическом сжатии данных (архиваторы ZIP, форматы JPEG, MP3) предварительно строится частотный словарь символов входного потока. Символам с высокой частотой встречаемости присваиваются самые короткие префиксные битовые коды, а редким символам — более длинные. Это минимизирует математическое ожидание длины сжатого файла (энтропию Шеннона).

### 7.2. Криптоанализ шифров простой замены
В классической криптографии моноалфавитные шифры (например, шифр Цезаря или случайная подстановка) сохраняют относительную частоту появления букв алфавита. Аналитик строит частотный словарь зашифрованного сообщения и сопоставляет пики частот с известными частотами букв естественного языка (в русском языке самая частая буква — «о», за ней следуют «е», «а», «и»; самые редкие — «ф», «ъ»). Это позволяет расшифровать текст без знания секретного ключа.

### 7.3. Информационный поиск: Инвертированный индекс
Поисковые системы (Яндекс, Google) индексируют триллионы веб-страниц, создавая гигантские ассоциативные массивы — **инвертированные индексы (Inverted Indexes)**. Ключом является лексема (слово), а значением — список идентификаторов веб-документов и позиций, где это слово встречается. Благодаря хэш-таблицам поисковый запрос обрабатывается за доли миллисекунды.

### 7.4. Метрика TF-IDF и фильтрация спама
В машинном обучении и анализе текстов значимость слова оценивается через частоту термина:
- **TF (Term Frequency):** Отношение числа вхождений слова к общему числу слов в документе;
- **IDF (Inverse Document Frequency):** Обратная частота слова во всей коллекции документов (подавляет шумовые слова-предлоги, такие как «и», «в», «не»).
Наивный байесовский классификатор спама использует словари вероятностей появления характерных слов («акция», «выигрыш», «кредит») для автоматической фильтрации почтовых сообщений.

## 8. Итоговый конспект и ключевые выводы

1. **Ассоциативный массив** — модель отображения `K → V`, хранящая уникальные ключи и ассоциированные с ними значения.
2. **Хэш-таблица** реализует ассоциативный массив со средней сложностью операций `O(1)` за счет вычисления индекса ячейки функцией `h(key) mod M`.
3. **Коллизия** возникает, когда разные ключи дают одинаковый индекс. Она разрешается методом цепочек (списки в ячейках) или открытой адресацией (пробирование пустых ячеек).
4. **Коэффициент заполнения `α = N / M`** определяет нагрузку на таблицу. При его превышении выполняется автоматическое **рехэширование** с удвоением размера таблицы.
5. Для построения **алфавитно-частотного словаря** текст нормализуется, разбивается на токены, подсчитывается хэш-таблицей и сортируется двухкритериальным компаратором: `(-count, word)`.
