# ⚙️ Сложность вычислений. Классы P и NP. NP-полные задачи (по К.Ю. Полякову)

## 1. Понятие вычислительной сложности алгоритма 📜

При изучении алгоритмов в курсе информатики ключевыми вопросами являются не только их правильность (корректность) и завершаемость, но и **эффективность**. Если алгоритм корректен, но для обработки массива из миллиона записей ему требуются тысячи лет машинного времени или терабайты оперативной памяти, такой алгоритм практически бесполезен.

Раздел теоретической информатики, исследующий зависимость объема необходимых вычислительных ресурсов от размера входных данных, называется **теорией сложности вычислений** (*Computational Complexity Theory*).

```
                      РЕСУРСЫ ВЫЧИСЛИТЕЛЬНОЙ СИСТЕМЫ:
                                     │
          ┌──────────────────────────┴──────────────────────────┐
          ▼                                                     ▼
┌─────────────────────────────────┐   ┌─────────────────────────────────┐
│  ВРЕМЕННАЯ СЛОЖНОСТЬ (Time)     │   │  ЕМКОСТНАЯ СЛОЖНОСТЬ (Space)    │
│  T(n) — количество элементарных │   │  M(n) — объем оперативной       │
│  шагов процессора (тактов,      │   │  памяти, необходимый для        │
│  сравнений, перестановок).      │   │  хранения данных и переменных.  │
└─────────────────────────────────┘   └─────────────────────────────────┘
```

### 1.1 Размер входа задачи (n)
Сложность любого алгоритма всегда выражается как математическая функция от **размера входа n**:
* Для алгоритмов сортировки и поиска `n` — это количество элементов в массиве или списке.
* Для графовых задач размер входа характеризуется числом вершин `|V|` и числом ребер `|E|`.
* В теоретической модели (на машинах Тьюринга) размер входа `n` — это **длина записи входных данных в битах** (или количество ячеек ленты, занятых словом).

### 1.2 Худший, средний и лучший случаи поведения
Время работы одного и того же алгоритма на входах одинакового размера `n` может существенно различаться в зависимости от структуры данных:
1. **Наилучший случай (Best Case):** Минимальное время выполнения на самых благоприятных входных данных. Например, для сортировки вставками или пузырьком на уже отсортированном массиве требуется всего `O(n)` операций.
2. **Средний случай (Average Case):** Математическое ожидание времени выполнения при равномерном распределении всех возможных вариантов входа. Например, алгоритм быстрой сортировки (QuickSort) в среднем выполняет `O(n log n)` операций.
3. **Наихудший случай (Worst Case):** Максимальное время работы на самых неблагоприятных данных. В теории сложности и промышленной разработке базовой метрикой является именно **оценка худшего случая**, так как она дает **строгую гарантию надежности**: алгоритм ни при каких обстоятельствах не превысит это время. Для QuickSort при неудачном выборе опорного элемента худший случай составляет `O(n<sup>2</sup>)`.

## 2. Асимптотический анализ и O-нотация (О-большое) 📈

В реальных компьютерах время работы зависит от тактовой частоты процессора, компилятора, архитектуры кэш-памяти и операционной системы. Чтобы сравнивать алгоритмы независимо от конкретного «железа», используют **асимптотический анализ** — исследование поведения функции сложности при стремлении размера входа `n` к бесконечности (`n → ∞`).

### 2.1 Математическое определение O-нотации (Нотация Бахмана — Ландау)
Говорят, что функция `T(n)` имеет порядок роста `O(f(n))` (читается: *«Тэ от эн есть О-большое от эф от эн»*), если существуют положительная константа `c > 0` и пороговое число `n<sub>0</sub> > 0`, такие что для всех `n ≥ n<sub>0</sub>` выполняется неравенство:

`T(n) ≤ c · f(n)`

```
  Время T(n)
      ▲
      │                 / c · f(n) (Верхняя асимптотическая граница)
      │                /
      │      /\       /
      │     /  \__   /  T(n) (Реальное время алгоритма)
      │    /      \_/
      │   /        /
      │  /        /
      │ /        /
      └─────────┴────────────────► Размер входа n
               n₀
```

### 2.2 Правила вычисления асимптотики:
1. **Игнорирование постоянных множителей:** Константы не зависят от размера задачи. `O(5n) = O(n)`, `O(100n<sup>2</sup>) = O(n<sup>2</sup>)`.
2. **Правило доминирующего слагаемого:** При сложении функций разного порядка учитывается только слагаемое с наивысшей скоростью роста при `n → ∞`.  
   Например, если точное число операций равно `T(n) = 3n<sup>3</sup> + 45n<sup>2</sup> + 1200n + 8000`, то асимптотическая сложность равна `O(n<sup>3</sup>)`.

## 3. Иерархия основных классов сложности функций 🧗

Скорость роста функций сложности различается колоссально. В информатике принято выделять следующие стандартные классы:

| Класс сложности | Название | Примеры классических алгоритмов и операций |
| :---: | :---: | :--- |
| **O(1)** | Константная | Доступ к элементу массива по индексу, получение размера коллекции, операции со стеком (`push`/`pop`), вставка в хэш-таблицу в среднем. |
| **O(log n)** | Логарифмическая | Двоичный (бинарный) поиск в отсортированном массиве, поиск в сбалансированных деревьях (АВЛ, красно-черные), алгоритм Евклида для НОД. |
| **O(n)** | Линейная | Линейный поиск элемента, подсчет суммы или максимума массива, один проход циклом по строке. |
| **O(n log n)** | Квазилинейная (линейно-логарифмическая) | Эффективные алгоритмы сортировки (MergeSort, HeapSort, QuickSort в среднем), быстрое преобразование Фурье (БПФ). Это теоретический предел для сортировок сравнениями! |
| **O(n<sup>2</sup>)** | Квадратичная | Простые сортировки (пузырьковая, вставками, выбором), перебор всех пар элементов, проверка пересечения отрезков «в лоб». |
| **O(n<sup>3</sup>)** | Кубическая | Классическое умножение матриц размера `n × n`, алгоритм Флойда — Уоршелла для поиска кратчайших путей между всеми парами вершин. |
| **O(n<sup>k</sup>)** | Полиномиальная (общая) | Алгоритмы с полиномиальной границей степени `k` (алгоритм сжатия, базовые алгоритмы линейной алгебры). |
| **O(2<sup>n</sup>)** | Экспоненциальная | Перебор всех подмножеств множества из `n` элементов, точное решение задачи о рюкзаке полным перебором, тривиальный поиск клики. |
| **O(n!)** | Факториальная | Перебор всех перестановок `n` элементов, точное решение задачи коммивояжера полным перебором маршрутов. |

### 3.1 Экспоненциальный взрыв (Катастрофа роста) 💥
Чтобы осознать пропасть между полиномиальными и экспоненциальными алгоритмами, представим суперкомпьютер, выполняющий **1 миллиард операций в секунду (10<sup>9</sup> оп/с, 1 ГГц)**:

| Размер задачи n | O(n) | O(n<sup>2</sup>) | O(n log n) | O(2<sup>n</sup>) | O(n!) |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **n = 10** | 0.00001 мс | 0.0001 мс | 0.00003 мс | 0.001 мс | 3.6 мс |
| **n = 20** | 0.00002 мс | 0.0004 мс | 0.00009 мс | 1 мс | **77 лет** |
| **n = 50** | 0.00005 мс | 0.0025 мс | 0.00028 мс | **35.7 лет** | 10<sup>47</sup> лет |
| **n = 100** | 0.0001 мс | 0.01 мс | 0.00066 мс | **4 × 10<sup>13</sup> лет** *(в 3000 раз старше Вселенной!)* | 10<sup>140</sup> лет |

> 📌 **Вывод К.Ю. Полякова:** Алгоритмы с экспоненциальной `O(2<sup>n</sup>)` и факториальной `O(n!)` сложностью принципиально неприменимы для реальных вычислений при сколько-нибудь значительных `n` (`n ≥ 50–100`). Рост мощности процессоров здесь бессилен: увеличение быстродействия в 1000 раз позволяет увеличить размер решаемой задачи всего на десяток элементов!

## 4. Классы сложности P и NP 🏛️

Центральное место в современной теории вычислений занимает классификация задач по признаку принципиальной возможности их эффективного решения.

В теории алгоритмов рассматриваются **задачи распознавания (проблемы разрешения, Decision Problems)** — задачи, на которые для любого входного слова требуется дать однозначный ответ: **«ДА» (1)** или **«НЕТ» (0)**. Любую оптимизационную задачу (например, «найти кратчайший путь») можно легко свести к задаче распознавания («существует ли путь длиной не более `L`?»).

```
                      КЛАССИФИКАЦИЯ СЛОЖНОСТИ ЗАДАЧ:
┌────────────────────────────────────────────────────────────────────────┐
│  КЛАСС NP (Nondeterministic Polynomial)                                │
│  Задачи, решение которых можно БЫСТРО ПРОВЕРИТЬ (за полиномиальное      │
│  время O(nᵏ)) при наличии сертификата (подсказки-свидетеля).           │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │  КЛАСС P (Polynomial)                                          │   │
│   │  Задачи, которые можно БЫСТРО РЕШИТЬ на обычном компьютере     │   │
│   │  (за полиномиальное время O(nᵏ)).                              │   │
│   │  (Сортировка, поиск пути в графе, умножение матриц, 2-SAT)    │   │
│   └────────────────────────────────────────────────────────────────┘   │
│                                                                        │
│   NP-ПОЛНЫЕ ЗАДАЧИ (NPC) — самые трудные в NP                          │
│   (SAT, 3-SAT, задача коммивояжера, рюкзак, клика, раскраска графа)    │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.1 Класс P (Polynomial)
**Класс P** — это класс задач распознавания, которые могут быть **решены детерминированным алгоритмом** (на детерминированной машине Тьюринга или обычном компьютере) за **полиномиальное время**, то есть время работы ограничено `O(n<sup>k</sup>)` для некоторой постоянной `k`.

Задачи класса P считаются **практически разрешимыми (вычислимыми)**. Примеры:
* Поиск элемента в массиве (`O(n)`).
* Проверка связности графа и поиск кратчайшего пути (алгоритмы Дейкстры, поиска в ширину BFS — `O(V + E)` или `O(V<sup>2</sup>)`).
* Нахождение наибольшего общего делителя (алгоритм Евклида — `O(log n)`).
* Проверка простоты числа (полиномиальный тест Агравала — Каяла — Саксены AKS, 2002 год).

### 4.2 Класс NP (Nondeterministic Polynomial)
Существует огромное число задач, для которых полиномиальный алгоритм решения неизвестен, однако **проверить предложенное решение** можно молниеносно.

**Класс NP** определяется двумя эквивалентными способами:
1. **Через недетерминированную машину Тьюринга (НМТ):** Класс задач, разрешимых за полиномиальное время на недетерминированной машине Тьюринга, которая обладает свойством «магического угадывания» правильной ветви вычислений.
2. **Через полиномиальную верификацию (Сертификат):** Задача принадлежит классу NP, если для любого положительного ответа («ДА») существует краткое свидетельство — **сертификат (подсказка)** полиномиальной длины, правильность которого можно проверить на обычном детерминированном компьютере **за полиномиальное время**.

#### Наглядный пример: Судоку и Разложение на множители
* Решить кроссворд Судоку размером `n<sup>2</sup> × n<sup>2</sup>` сложно (требуется перебор вариантов).
* Но если вам принесли уже заполненную сетку (сертификат), проверить отсутствие дубликатов в строках, столбцах и блоках можно мгновенно за один цикл `O(n<sup>2</sup>)`. Значит, задача принадлежит классу NP!
* Проверка сертификата для факторизации: если дано число `N` из 600 цифр, найти его простые делители колоссально трудно. Но если кто-то утверждает, что делителями являются `p` и `q`, проверить это тривиально: умножить `p × q` на обычном калькуляторе за доли секунды.

### 4.3 Очевидное включение P ⊆ NP
Любая задача из класса P автоматически входит в класс NP:
`P ⊆ NP`
*Доказательство:* Если задачу можно решить за полиномиальное время, то для проверки сертификата можно вообще проигнорировать подсказку, заново решить задачу полиномиальным алгоритмом и сверить результат.

## 5. Великая проблема «P против NP» (P versus NP) ❓

Главный фундаментальный вопрос теоретической информатики, сформулированный независимо Стивеном Куком (1971) и Леонидом Левиным (1973), звучит предельно просто:

> ⚖️ **Верно ли, что P = NP?**  
> То есть: если правильность любого решения можно быстро проверить за полиномиальное время, верно ли, что само это решение всегда можно так же быстро найти?

```
                 ДВЕ ГИПОТЕЗЫ О СТРОЕНИИ МИРА:

      Гипотеза 1: P ≠ NP (Большинство ученых)       Гипотеза 2: P = NP
      
      ┌─────────────────────────────┐               ┌─────────────────────────────┐
      │        КЛАСС NP             │               │                             │
      │   ┌─────────────────────┐   │               │                             │
      │   │       КЛАСС P       │   │               │           P = NP            │
      │   │  (Легкие задачи)    │   │               │   (Все проверяемое легко    │
      │   └─────────────────────┘   │               │    находится алгоритмически)│
      │   NP-полные (Самые      │   │               │                             │
      │   трудные задачи в NP)  │   │               │                             │
      └─────────────────────────────┘               └─────────────────────────────┘
```

### 5.1 Статус проблемы тысячелетия
Математический институт Клэя (Clay Mathematics Institute) в 2000 году включил проблему «P против NP» в список **Семи математических задач тысячелетия**, назначив за ее строгое доказательство премию в **$1 000 000**.

Подавляющее большинство специалистов в области Computer Science убеждены, что **P ≠ NP** (проверять стихи, музыку или доказательства теорем принципиально легче, чем создавать их с нуля). Однако математического доказательства этого факта не существует до сих пор.

### 5.2 Что произойдет, если однажды докажут, что P = NP?
Если окажется, что `P = NP`, мир фундаментально изменится:
1. **Крах криптографии и банковских систем:** Вся современная электронная коммерция, блокчейн, протоколы HTTPS/TLS, шифрование RSA и эллиптические кривые (ECC) основаны на предположении вычислительной трудности факторизации и дискретного логарифмирования. При `P = NP` любые пароли и закрытые ключи будут вычисляться за доли секунды.
2. **Автоматизация науки:** Компьютеры смогут мгновенно генерировать формальные математические доказательства любых непроверенных гипотез.
3. **Революция в медицине и логистике:** Идеальное сворачивание белковых молекул, нахождение лекарств от онкологии, абсолютно оптимальная глобальная маршрутизация транспорта без пробок.

## 6. Полиномиальная сводимость задач 🔄

Как доказать, что одна задача не проще другой? Для этого используется аппарат **сведения**.

### 6.1 Определение полиномиальной сводимости по Карпу (≤<sub>p</sub>)
Задача `A` **полиномиально сводится** к задаче `B` (обозначается `A ≤<sub>p</sub> B`), если существует функция преобразования `f`, вычислимая за **полиномиальное время**, которая переводит любой входной экземпляр `x` задачи `A` во входной экземпляр `f(x)` задачи `B` так, что:

Ответ на `x` в задаче `A` равен «ДА» ⟺ Ответ на `f(x)` в задаче `B` равен «ДА».

```
                     СХЕМА СВЕДЕНИЯ A ≤ₚ B:
                     
Вход задачи A (x) ───► [ Полиномиальный транслятор f ] ───► Экземпляр f(x)
                                                                   │
                                                                   ▼
Результат «ДА» / «НЕТ» ◄───────────────────────────────── [ Алгоритм для B ]
```

### 6.2 Свойства сводимости:
1. **Перенос разрешимости:** Если `A ≤<sub>p</sub> B` и для задачи `B` существует полиномиальный алгоритм, то и задача `A` решается за полиномиальное время.
2. **Перенос трудности:** Если известно, что задача `A` трудна (не решается за полиномиальное время), то и задача `B` заведомо не может решаться полиномиально. Задача `B` «как минимум так же сложна, как `A`».
3. **Транзитивность:** Если `A ≤<sub>p</sub> B` и `B ≤<sub>p</sub> C`, то `A ≤<sub>p</sub> C`.

## 7. NP-полные и NP-трудные задачи 🎯

Среди необозримого множества задач класса NP ученые выделили узкое ядро «критических» задач, обладающих уникальным свойством.

### 7.1 Определение NP-полноты (NP-Complete, NPC)
Задача `L` называется **NP-полной (NP-Complete)**, если выполняются строго два критерия:
1. `L ∈ NP` (задача принадлежит классу NP, то есть ее решение проверяется за полиномиальное время).
2. Для **любой** задачи `M ∈ NP` справедливо сведение `M ≤<sub>p</sub> L` (все без исключения задачи из NP полиномиально сводятся к `L`).

> 💡 **Следствие феномена NP-полноты:**
> Все NP-полные задачи эквивалентны по сложности с точностью до полинома. Если будет найден быстрый (полиномиальный) детерминированный алгоритм решения хотя бы для **одной** NP-полной задачи, то **все задачи из класса NP будут мгновенно решены за полиномиальное время**, и тем самым будет доказано равенство **P = NP**!

### 7.2 NP-трудные задачи (NP-hard)
Задача называется **NP-трудной (NP-hard)**, если к ней полиномиально сводится любая задача из класса NP, но сама она **не обязана принадлежать классу NP**:
* К NP-трудным относятся оптимизационные версии задач (например, точный поиск маршрута коммивояжера минимальной длины, а не просто ответ «меньше ли длина числа L»).
* К NP-трудным относятся даже алгоритмически неразрешимые задачи! Например, классическая **задача останова Тьюринга** является NP-трудной, так как к ней можно свести любую задачу, но она вообще не имеет алгоритма решения.

## 8. Теорема Кука — Левина и канонические задачи 👑

Долгое время определение NP-полноты оставалось абстракцией: не было известно, существует ли в природе хоть одна такая универсальная задача.

### 8.1 Теорема Кука — Левина (1971 г.)
Американский ученый **Стивен Кук** (1971) и независимо советский математик **Леонид Левин** (1973) совершили научный прорыв, доказав базовую теорему:

> 📜 **Теорема Кука — Левина:**
> Задача выполнимости булевых формул (**SAT** — *Boolean Satisfiability Problem*) является **NP-полной**.

#### В чем состояла гениальность доказательства?
Кук и Левин не знали других NP-полных задач. Они взяли само математическое определение **недетерминированной машины Тьюринга (НМТ)** и доказали, что работу произвольной НМТ за полиномиальное число шагов `p(n)` можно напрямую закодировать гигантской булевой формулой. Переменные формулы кодировали положение головки, состояния и содержимое ячеек ленты, а конъюнкция дизъюнктов гарантировала соблюдение правил перехода. Формула оказывалась выполнимой тогда и только тогда, когда машина Тьюринга приходила в допускающее состояние.

### 8.2 Метод домино: доказательство NP-полноты через сведение
После того как первая NP-полная задача (SAT) была найдена, для доказательства NP-полноты любой новой задачи `X` больше не нужно мучительно моделировать машину Тьюринга. Достаточно выполнить два шага:
1. Показать, что `X ∈ NP` (предъявить полиномиальный верификатор).
2. Выбрать **уже известную** NP-полную задачу `Y` (например, SAT или 3-SAT) и построить сведение `Y ≤<sub>p</sub> X`.

В 1972 году американский ученый **Ричард Карп** опубликовал знаменитую работу *«Сводимость комбинаторных проблем»*, доказав NP-полноту сразу 21 классической задачи информатики («21 задача Карпа»).

```
                      ЦЕПОЧКА СВЕДЕНИЙ РИЧАРДА КАРПА:
                      
                             [ SAT (Кук-Левин) ]
                                      │
                                      ▼
                                  [ 3-SAT ]
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
  [ КЛИКА (CLIQUE) ]         [ ВЕРШИННОЕ ПОКРЫТИЕ ]     [ СУММА ПОДМНОЖЕСТВА ]
          │                           │                           │
          ▼                           ▼                           ▼
[ НЕЗАВИСИМОЕ МНОЖЕСТВО ]  [ ГАМИЛЬТОНОВ ЦИКЛ / TSP ]      [ РЮКЗАК (KNAPSACK) ]
```

## 9. Галерея классических NP-полных и NP-трудных задач 🖼️

В школьном курсе по учебнику К.Ю. Полякова рассматриваются хрестоматийные задачи, возникающие на практике.

### 9.1 Задача выполнимости булевой формулы (SAT и 3-SAT)
* **Дано:** Булева формула в конъюнктивной нормальной форме (КНФ), состоящая из скобок-дизъюнктов, объединенных знаком «И» (`∧`). В каждом дизъюнкте переменные или их отрицания объединены знаком «ИЛИ» (`∨`).
  * В задаче **3-SAT** в каждом дизъюнкте содержится ровно 3 литерала:  
    `(x<sub>1</sub> ∨ ¬x<sub>2</sub> ∨ x<sub>3</sub>) ∧ (¬x<sub>1</sub> ∨ x<sub>4</sub> ∨ ¬x<sub>3</sub>) ∧ ...`
* **Вопрос:** Существует ли такой набор логических значений переменных (`Истина / Ложь`), при котором вся формула обращается в `1`?
* **Статус:** 3-SAT является NP-полной задачей. При этом задача **2-SAT** (по 2 литерала в скобке) легко решается за полиномиальное линейное время `O(V + E)` и принадлежит классу P!

### 9.2 Задача о рюкзаке (Knapsack Problem)
* **Дано:** Набор из `n` предметов. Каждый предмет имеет вес `w<sub>i</sub>` и стоимость `v<sub>i</sub>`. Имеется рюкзак предельной грузоподъемности `W`.
* **Задача:** Выбрать подмножество предметов с суммарным весом не более `W`, имеющее максимальную суммарную ценность.
* **Статус:** NP-полная задача (в формулировке распознавания «можно ли набрать ценность не менее `V`?»). Полный перебор требует `O(2<sup>n</sup>)` шагов.

### 9.3 Задача коммивояжера (TSP — Travelling Salesperson Problem)
* **Дано:** Список из `n` городов и матрица расстояний между ними.
* **Задача:** Найти кратчайший замкнутый маршрут (гамильтонов цикл), проходящий через каждый город ровно по одному разу и возвращающийся в исходную точку.
* **Статус:** Задача нахождения гамильтонова цикла — NP-полная, а задача поиска минимума — NP-трудная. Полный перебор всех вариантов маршрутов требует проверки `(n - 1)! / 2` перестановок (факториальная сложность `O(n!)`). При `n = 30` перебор не завершится до угасания Солнца.

### 9.4 Задача о клике (Clique Problem)
* **Кликой** в графе называется подмножество вершин, в котором **каждые две вершины соединены ребром** (полный подграф).
* **Вопрос:** Содержит ли заданный граф клику из `k` вершин?
* **Применение:** Анализ социальных сетей (поиск сообществ взаимно знакомых людей), биоинформатика.

### 9.5 Задача о вершинном покрытии (Vertex Cover)
* **Вершинным покрытием** графа называется такое множество вершин, что каждое ребро графа инцидентно хотя бы одной вершине из этого множества.
* **Вопрос:** Существует ли вершинное покрытие размера не более `k`?
* **Применение:** Размещение минимального числа камер видеонаблюдения для контроля всех коридоров здания, расстановка сетевых маршрутизаторов.

### 9.6 Задача о раскраске графа (Graph Coloring)
* **Вопрос:** Можно ли раскрасить вершины графа не более чем в `k` цветов так, чтобы никакие две смежные вершины не имели одинакового цвета (хроматическое число графа `χ(G) ≤ k`)?
* **Статус:** Для `k = 2` задача лежит в классе P (проверка графа на двудольность через поиск в ширину). Для любого фиксированного `k ≥ 3` задача раскраски становится **NP-полной**.
* **Применение:** Составление расписания занятий (экзамены с общими студентами не могут проходить одновременно), распределение частот базовых станций сотовой связи.

## 10. Практические методы борьбы с NP-трудностью 🛠️

Что делать программисту на практике, если поставленная задача оказалась NP-полной, а ответ требуется получить в разумные сроки? Инженеры используют компромиссные подходы:

```
                  КАК РЕШАЮТ NP-ТРУДНЫЕ ЗАДАЧИ НА ПРАКТИКЕ:
                                     │
     ┌───────────────────────────────┼───────────────────────────────┐
     ▼                               ▼                               ▼
[ ПРИБЛИЖЕННЫЕ АЛГОРИТМЫ ]      [ ЭВРИСТИКИ И МЕТАЭВРИСТИКИ ]   [ ДИНАМИЧЕСКОЕ ПРОГРАММИРОВАНИЕ ]
Гарантируют полиномиальное       Быстро находят хорошее          Псевдополиномиальное время
время и точную границу           решение без формальных          O(n · W) для задач с
отклонения (1 + ε) от оптимума   гарантий (Генетические, Отжиг)  ограниченными числами (Рюкзак)
```

1. **Динамическое программирование (Псевдополиномиальные алгоритмы):**
   * Для задачи о рюкзаке существует алгоритм на базе динамического программирования со сложностью `O(n · W)`, где `W` — числовая вместимость рюкзака.
   * *Почему это не опровергает NP-полноту?* Потому что размер входа в теории сложности измеряется количеством **битов** числа `W`, то есть `L = log<sub>2</sub> W`. Функция `O(n · 2<sup>L</sup>)` является экспоненциальной от битовой длины входа! Такие алгоритмы называют *псевдополиномиальными*: они эффективны, пока числа `W` малы.
2. **Приближенные алгоритмы (Approximation Algorithms):**
   * Алгоритмы, работающие за полиномиальное время и гарантирующие, что найденное решение отличается от идеального не более чем на определенный множитель `(1 + ε)`.
   * *Пример:* 2-приближенный алгоритм для вершинного покрытия или алгоритм Кристофидеса с коэффициентом 1.5 для метрической задачи коммивояжера.
3. **Эвристические и вероятностные методы:**
   * Не дают строгой математической гарантии качества, но находят решения промышленного качества за доли секунды:
     * **Жадные алгоритмы:** выбор локально наилучшего шага (например, добавление ближайшего города в TSP).
     * **Метод имитации отжига (Simulated Annealing):** аналогия с охлаждением кристаллической решетки металла с вероятностным выходом из локальных минимумов.
     * **Генетические алгоритмы (Genetic Algorithms):** мутации, скрещивание и естественный отбор популяций решений.
     * **Муравьиные алгоритмы (Ant Colony Optimization):** моделирование феромонного следа на ребрах графа.
4. **Метод ветвей и границ (Branch and Bound):**
   * Умный перебор пространства состояний с отсечением целых ветвей дерева, в которых заведомо невозможно получить решение лучше текущего рекорда.

## 11. Дополнительная информация. Задание 1 (Уровень 1: Базовый — Механики манипуляции мышью) 🖱️

На первом уровне вам предстоит решать задачи на визуализацию и классификацию классов сложности и асимптотик с помощью физических действий мыши.

### 11.1 Механика и дидактические паттерны:
1. **Слот-конструирование асимптотического ряда:**
   * Расположение формул сложности в гнездах строго в порядке возрастания темпа роста при `n → ∞`:  
     `O(1) → O(log n) → O(n) → O(n log n) → O(n<sup>2</sup>) → O(n<sup>3</sup>) → O(2<sup>n</sup>) → O(n!)`.
   * Помните: логарифмическая функция растет медленнее любой степенной, а квазилинейная `O(n log n)` строго занимает промежуточное положение между линейной и квадратичной.
2. **Сортировка задач по функциональным корзинам (Классы P, NP, NP-Complete):**
   * **Корзина «Класс P» (Решаются быстро за полином):** Сортировка слиянием, поиск в ширину (BFS), проверка двудольности графа, нахождение минимального остовного дерева (алгоритм Краскала/Прима), алгоритм Евклида.
   * **Корзина «NP-полные задачи» (Труднейшие в NP):** 3-SAT, задача о клике, задача о вершинном покрытии, гамильтонов цикл, раскраска графа в 3 цвета, задача о рюкзаке.
   * **Корзина «NP-трудные / Неразрешимые»:** Задача останова машины Тьюринга, точная оптимизационная задача коммивояжера.
3. **Интерактивная коммутация графа сведений Карпа:**
   * Протягивание направленных связей сводимости `A ≤<sub>p</sub> B` между узлами:  
     `SAT → 3-SAT → Клика → Вершинное покрытие → Гамильтонов цикл`.

На втором уровне вам предстоит выполнять аналитические расчеты, исследовать полиномиальную сводимость и вводить точные вычисленные значения в поля `<input>`.

### 12.2 Разбор типовых аналитических фаз:
1. **Расчет количества элементарных шагов при росте входа:**
   * Определение кратности увеличения времени при росте `n` в `k` раз:

2. **Анализ асимптотики вложенных циклов:**
   * Определение порядка роста по коду на псевдокоде или Python:
     * Одиночный цикл `for i in range(n)` ➔ `O(n)`.
     * Вложенные циклы `for i in range(n): for j in range(n):` ➔ `O(n<sup>2</sup>)`.
     * Цикл с делением шага пополам `while n > 1: n //= 2` ➔ `O(log n)`.
3. **Определение истинности включений:**
   * Ввод логических вердиктов о структуре классов сложности:
     * Утверждение «Всякая задача из P лежит в NP» ➔ `Истина` (`TRUE`).
     * Утверждение «Если найдено полиномиальное решение для 3-SAT, то P = NP» ➔ `Истина` (`TRUE`).
     * Утверждение «Задача 2-SAT является NP-полной» ➔ `Ложь` (`FALSE`) (она принадлежит P).
4. **Расчет критических границ суперкомпьютера:**
   * Вычисление предельного размера задачи `n`, доступного для решения за 1 секунду при заданной частоте процессора (например, для `O(2<sup>n</sup>)` при `10<sup>9</sup>` операций в секунду предел `n ≈ 30`).

## 13. Дополнительная информация. Задание 3 (Уровень 3: Аркада — Финальный босс) ⚡

Финальный аркадный уровень представляет собой скоростной тренажер **«Complexity Core: Asymptotic Stabilizer»** (Архетип скоростной классификации и балансировки ресурсов).

### 13.1 Механика и экстремальный тайм-прессинг:
* На центральный вычислительный узел с нарастающей скоростью поступают входящие вычислительные задачи с заданными параметрами: размер входа `n`, выделенный лимит времени `T<sub>lim</sub>`, класс асимптотики или структурная сводимость.
* Игрок должен за секунды оценить ресурсный профиль задачи и принять верное инженерное решение:
  * Назначить адекватный класс алгоритма (точный полиномиальный, псевдополиномиальный, приближенный или метаэвристику);
  * Предотвратить экспоненциальный срыв ядра;
  * Парировать некорректные редукции сложности.
* **Правило хардкора:** Любая ошибка в оценке асимптотики или пропуск таймера приводит к перегрузке ядра (`SYSTEM OVERHEAT`), отправляет событие `hardcore_reset` и сбрасывает все волны на начальную позицию!

### 13.2 Стратегии скоростной идентификации на волнах испытания:
* **Мгновенный маркер полинома:** Если в задаче фигурирует остовное дерево, поиск пути или 2-SAT — это безопасный полиномиальный сектор `P`.
* **Мгновенный маркер NP-полноты:** Если появляются ключевые слова: «гамильтонов цикл», «клика размера k», «раскраска в 3 цвета», «разбиение чисел на равные суммы» — включайте эвристические шлюзы!
* Для победы удерживайте фокус на степени роста функций и помните: любая экспонента `2<sup>n</sup>` при `n > 40` мгновенно сжигает доступный лимит машинных тактов.
