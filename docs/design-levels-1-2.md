# Геймдизайн: Уровни 1 и 2 (Базовый и Продвинутый)

Задания загружаются в независимые `<iframe>` через систему вкладок платформы Astro. Не пишите логику переключения вкладок.
Для реализации данных уровней используется **Vanilla JS** (без фреймворков).

## Требования к механике
* **Уровень 1 (Базовый):** Состоит из **3 фаз (шагов)**. Простая механика (ввод ответа, выбор кнопок). 
* **Уровень 2 (Продвинутый):** Состоит из **5 фаз (шагов)**. **Строгий запрет на "кнопки выбора"**: механика требует исключительно ручного текстового ввода (анализ логов, исправление уязвимостей, парсинг данных). Так как глобальная вставка текста (Ctrl+V) запрещена платформой, ученику придется печатать ответ вручную, опираясь на теорию.

## ГЛАВНЫЙ ПРИНЦИП: Процедурная генерация и обработка ошибок
Для Уровней 1 и 2 **категорически запрещено** использовать статические (жестко заданные) массивы с небольшим числом вариантов.
1. Все задачи должны собираться на лету (процедурная генерация из кусочков: случайные числа, домены, логические операторы), обеспечивая десятки и сотни вариантов для каждой фазы.
2. Механики заданий должны быть направлены на тренировку когнитивных навыков, необходимых для ОГЭ (например, случайным образом просить найти разные элементы, чтобы заставить ученика всегда вчитываться в задачу).
3. **Обработка ошибок:** Ошибки на этих уровнях НЕ сбрасывают весь прогресс задания. При ошибке в любой фазе скрипт должен показать сообщение об ошибке, отправить телеметрию `hardcore_reset` и **сгенерировать НОВЫЙ уникальный вариант** для текущего шага (с визуальной задержкой 1-1.5 сек). Это полностью исключает метод "слепого перебора" без сильного раздражения игрока.
