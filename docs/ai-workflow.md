# Правила работы для ИИ-агентов (AI Workflow)

Так как разработка проекта School LMS полностью ведется автономными ИИ-агентами, к процессу взаимодействия с кодом применяются строгие правила во избежание деградации кодовой базы, потери контекста или конфликтов.

## 1. Запрет на работу в ветке `main`
* ИИ-агент **НИКОГДА** не должен писать код и делать коммиты напрямую в ветку `main`.
* Получив задачу, агент обязан:
  1. Убедиться, что он находится в `main` и получить последние изменения (`git checkout main`, `git pull`).
  2. Создать новую ветку под свою задачу (`git checkout -b type/task-name`, где `type` это `feat`, `fix`, `docs`, `content`).
  3. Вести всю работу исключительно в этой ветке.

## 2. Использование контекста и документации
* Агенту **ЗАПРЕЩАЕТСЯ** "гадать" или писать код по памяти.
* Перед началом работы агент **ОБЯЗАН** прочитать `AGENTS.md` и загрузить в контекст только те `.md` файлы из папки `docs/`, которые непосредственно относятся к задаче.
* Агент должен использовать утилиты для просмотра структуры файлов (например, `Get-ChildItem` в PowerShell), чтобы убедиться в существовании файлов, прежде чем пытаться их изменить.

## 3. Изоляция изменений (Zero-Breakage Policy)
* Изменяя существующий компонент или логику (например, `Layout.astro` или `[id].astro`), агент должен минимизировать область изменений.
* Запрещается удалять существующие `id`, классы или функции, если это явно не требуется задачей, так как от них могут зависеть другие скрипты или тренажеры (iframe).

## 4. Оформление коммитов
Коммиты должны быть атомарными и следовать формату Conventional Commits:
* `feat:` - новый функционал.
* `fix:` - исправление ошибки.
* `docs:` - изменения в документации.
* `content:` - добавление или изменение уроков/заданий (специфично для этой LMS).
Пример: `git commit -m "content: добавлены задания для урока 10 класса по сетям"`

## 5. Завершение задачи (Pull Request)
* Закончив задачу, агент должен запушить ветку в удаленный репозиторий: `git push -u origin branch-name`.
* Агент должен предложить пользователю проверить изменения или создать Pull Request через GitHub CLI (`gh pr create`), если этот инструмент доступен, снабдив PR подробным описанием того, что было изменено и как это тестировать.

## 6. Защита данных
* ИИ-агенту строго запрещается снимать комментарии с исключений в `.gitignore`. База данных `telemetry.db` и файлы с секретами (например, `.env`) **никогда** не должны попадать в индекс git.
